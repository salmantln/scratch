# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

QuietNote is a local-first meeting workspace built on top of **Scratch** (Eric Li's markdown notes app). It is Tauri v2 (Rust) + React 19/TypeScript/Tailwind v4 + TipTap + Tantivy. Meetings are the primary object. On macOS and Windows, capture is real: Rust records the mic and system audio and transcribes them locally with whisper.cpp, then removes filler words with delete-only rules (the raw words are kept). The browser preview and Linux keep a **prototype** capture that records nothing. There is no AI summarization, cloud processing, cloud sync or accounts. Do not fabricate those behaviors (e.g. inventing summaries, transcripts or audio). The only runtime network use is Connections: an explicit, user-initiated send of action items to Linear or GitHub. The speech models are downloaded at build time only.

Upstream Scratch code is retained, not rewritten. The QuietNote shell lives in `src/quietnote/` and `src-tauri/src/meetings.rs` and reuses Scratch's editor, services and Rust commands. `docs/SCRATCH-AUDIT.md` (pre-change audit) and `docs/MODIFIED-FILES.md` (diff manifest vs. upstream) are the reference for what was changed. Keep `docs/MODIFIED-FILES.md` in sync when touching upstream files.

## Commands

```bash
npm run dev          # Vite dev server at http://localhost:1420 (browser preview, localStorage-backed)
npm run tauri dev    # Full desktop app with real filesystem (runs `npm run models` first)
npm run models       # Fetch the bundled speech models into src-tauri/resources/models (≈575 MB, SHA-256 pinned, gitignored)
npm run build        # tsc + vite build
npm run typecheck    # tsc --noEmit across all frontend code
npm run lint         # ESLint — only covers src/quietnote, tests and tooling config (upstream Scratch code is not linted)
npm test             # Playwright tests (auto-starts the dev server)
npx playwright test -g "one recording at a time"   # run a single test by name
cargo test --manifest-path src-tauri/Cargo.toml # Rust unit tests (meetings, capture, cleanup, transcript, connectors)
QUIETNOTE_TEST_AUDIO=/dir/with/wavs cargo test --release --manifest-path src-tauri/Cargo.toml transcribes -- --ignored --nocapture  # run the real model
QUIETNOTE_LIVE_SECONDS=300 cargo test --release --manifest-path src-tauri/Cargo.toml records_live -- --ignored --nocapture   # record from this Mac's real devices
npm run tauri build -- --debug --bundles app    # macOS dev bundle
```

Playwright needs Chromium (`npx playwright install chromium`). Tests run serially (1 worker) against the browser preview in fresh contexts, so they never touch the real desktop archive. Tests J–N drive the desktop recording UI through `mockDesktop(page, fixture)`, a hand-written stand-in for `window.__TAURI_INTERNALS__` that models only the recording commands and events (fixture: meetings, microphone permission, model status, a live recording, a start failure). `docs/QA-RECORDING.md` is the manual real-device checklist, `docs/PERFORMANCE.md` the measured numbers, and `docs/WINDOWS.md` the untested Windows risks.

CI (`.github/workflows/ci.yml`) runs `npm run build`, `cargo check` and `cargo clippy -- -D warnings` on Ubuntu (which doesn't compile the recorder), plus clippy on all targets and `cargo test` on macOS with the models cached; lint, typecheck and Playwright must be run locally. The release workflow is manual (`workflow_dispatch`) and creates a draft only; the upstream Scratch update feed is disconnected (update checks are gated on `VITE_QUIETNOTE_UPDATES`).

## Architecture

### Two apps in one bundle
`src/main.tsx` picks the root component from the URL:
- default → `QuietNoteApp` (the meetings shell)
- `?workspace=…` or `?mode=preview` → upstream Scratch `App` (generic Markdown workspace / standalone file preview), lazy-loaded

The Scratch workspace is reachable from Settings → Local archive → Open Markdown workspace, and links back to QuietNote from its About screen.

### QuietNote shell (`src/quietnote/`)
- `QuietNoteApp.tsx`: single `Shell` component that owns all state (meetings, projects, view, selection, save status, drafts, banners, keyboard shortcuts, window-close handling). Views: home / all / project / meeting / search / settings (a remembered `recent` from earlier builds opens Home). With no projects and no meetings it renders the first-run `Welcome` screen instead of the shell. The last view, meeting and tab are remembered in localStorage (`quietnote.place.v1`).
- `Library.tsx`: `MeetingList` (rows grouped by day; today's show the time; a row without a status shows its open action-item count) and `Home`. Home is laid out top to bottom:
  - A capture card built from `CaptureState`: ready, mic denied (Open System Settings), model missing, recording (Open meeting only, on Notes; Stop stays in `RecordingBar`, so there's never a second one), transcribing % and queue, or prototype. Start recording calls `newMeeting()`.
  - A search field that switches to Search.
  - Open action items from every meeting. A tick goes through `persist` + `toggleAction`, and a ticked item stays struck through until you leave Home.
  - The ten latest meetings.

  Empty sections are hidden.
- `Dialogs.tsx` (`Modal`, new project, new meeting; with `canRecord` its primary button is "Start recording", which creates the meeting and starts recording it, and "Create meeting" is secondary), `Capture.tsx` and `Settings.tsx` (Privacy / Local archive / About). `Capture` is not a dialog: `MeetingDetail` renders it as a strip under the tabs (region "Recorder") while its meeting is armed to start (the Shell's `capture`, dropped on leaving the meeting or when its recording stops) or recording, so Notes and the transcript stay usable. It renders `Recorder` when `CaptureState.available` (a view over Rust state: one line with elapsed time from `startedAt`, mic/call-audio levels and Stop; device problems, notes and silent-track hints with Open System Settings go below it. While the mic permission is `undetermined` it expands into the first-run explainer with Cancel / Start recording instead of starting automatically, so the explanation always comes before the macOS prompt; a `mic-denied` start failure shows Open System Settings and Try again) and otherwise `Prototype` (browser preview and Linux: `idle` → `recording` → `ready` from the meeting's metadata, records nothing, no simulated processing). There's no "ended" step: after Stop the strip goes and the meeting's transcribing notice takes over.
- `model.ts`: `Meeting = { metadata, markdown, transcript }` plus pure helpers for reading and writing `##` sections of `meeting.md` (`section`, `replaceSection`, `toggleAction`, `appendItem`), parsing (`decisions`, `actionItems` with `Owner — task`, `transcriptTurns` from `### mm:ss Speaker`), and search context (`searchMeeting` returns the matching tab and a snippet). The **Notes** section is always last and consumes the rest of the file, so headings inside notes survive.
- `storage.ts`: persistence facade that branches on `isTauri()`:
  - **Desktop**: `invoke()` calls into `meetings.rs` for archive load/create/metadata/preferences. Markdown is saved with Scratch's `saveFileDirect`. On load it points Scratch's notes folder at the archive root and starts its file watcher, so Tantivy search (`indexedSearch`) works over meeting files.
  - **Browser preview**: everything goes to `localStorage` (`quietnote.preview.archive.v1`, `quietnote.preview.projects.v1`, `quietnote.privacy`). It never migrates into the desktop app.
  - Desktop saves are recorded in `ownWrites` so the watcher's `file-change` events for QuietNote's own writes don't trigger the "Files changed outside QuietNote" prompt. Rust's `transcript.md` writes are recorded the same way when `quietnote://meeting-changed` arrives.
  - Recording: `captureStatus`/`captureStart` (rejects with `CaptureFailure { code: 'mic-denied' | 'disk' | 'failed', message }`)/`captureStop`/`transcribe`/`transcriptData`/`renderTranscripts`/`revealAudio`/`openPrivacySettings`. The Shell keeps `live: CaptureState` from `quietnote://capture-state` and upserts meetings from `quietnote://meeting-changed` (metadata, a finished transcript, or a problem shown as a banner). While recording, `RecordingBar` in the window header shows the title, elapsed time (`model.clock`, the same format as the tray) and Stop in every view except the recording meeting itself, where the recorder strip has the only Stop. However a recording stops (recorder, bar, tray, low disk), a "Recording saved" banner (then "Transcript ready") with Open meeting says where it went, unless that meeting is open. A banner lists meetings with `interrupted` ("Recovered recording").
- `MeetingDetail.tsx`: tabs (Summary / Decisions / Action items / Notes / Transcript). The Notes tab lazy-loads Scratch's real `components/editor/Editor` inside `NotesBoundary`, so an editor failure shows "Notes couldn't open." with Reload instead of blanking the window; `Crashed` in `QuietNoteApp.tsx` does the same for the whole shell. Summary, decisions and tasks are parsed from Markdown, not stored separately. An idle meeting's Start recording is its primary action, starts at once and switches to Notes (there's no confirm step; the first-run explainer still waits); New meeting's Start recording also opens on Notes. The recorder strip sits where the notices go. Notices for a recovered recording (`interrupted`, with Dismiss), transcribing (progress) and error (with audio: "Transcription couldn't finish. Your recording is still saved", Show audio, Retry transcription, and the stored `error` under Details; without: the interrupted copy). Start recording is disabled while another meeting records. `find` prefills Find in transcript when opened from a transcript search hit. A recorded transcript has a Clean / Verbatim toggle (default from the `cleanTranscript` preference, with a caption); both views come from `transcript_data` and switching never writes.
- `Connectors.tsx` (`ConnectionsDialog`, the searchable directory opened from the sidebar; `SendDialog`, which sends a meeting's unsent open action items as issues) and `catalog.ts` (directory entries). Brand logos are static SVGs in `src/quietnote/brands/` (credited in NOTICE). Apple Calendar, Reminders and Things icons are read from the installed apps via `connector_app_icons`, with a letter tile as fallback. `issueFor` in `model.ts` builds the issue from an item. Only entries with a `service` (Linear, GitHub) connect; all others are Planned and have no action. A sent item keeps its link at the end of its Markdown line (`linkAction`, parsed into `ActionItem.link`). Example meetings can't be sent.
- `seeds.ts`: six demo meetings. They are **not** seeded automatically. They are written only via "Explore example meetings" / "Add examples" (`storage.addExamples`, which skips existing ids), and are identified by id with `isExample` so they're always badged Example.

### Rust side
- `src-tauri/src/meetings.rs`: QuietNote commands (`load_meeting_archive` returns `{ root, projects, meetings }` where projects are top-level archive folders; `create_project`; `create_meeting_bundle`; `save_meeting_metadata`; `quietnote_preferences`). Metadata and preferences are written atomically (temp file + rename). Path components are validated with `safe_component`.
- `src-tauri/src/connectors.rs`: Linear (GraphQL) and GitHub (REST) via `reqwest`. `connector_connect` verifies a key before storing it in the macOS Keychain (`keyring`, macOS-only dependency; other platforms return an error). Keys never return to the webview. Account labels go in `<app data>/connections.json`. `connector_app_icons` reads installed app icons through `NSWorkspace` (`objc2-app-kit`). All HTTP happens in Rust, so the CSP has no `connect-src`.
- `src-tauri/src/capture.rs`: the recording/transcription lifecycle and its commands (`capture_status`, `capture_start`, `capture_stop`, `transcribe_meeting`, `transcript_data`, `render_transcripts`, `open_privacy_settings`). Managed state `Capture` holds the one live `Session` (start as wall clock, so window and tray agree) and a FIFO transcription queue with a single worker thread; `claim()` allows one recording at a time. `State` also carries the microphone permission and the model status (ready/missing/damaged). Rust owns a meeting's status while it records or transcribes (`owns`; `save_meeting_metadata` refuses those meetings): `idle` → `recording` (audio folder set) → `processing` → `ready`, or `error` with the audio kept and the reason in `metadata.error`. Start is refused below 1 GB free; the ticker warns below 1 GB and stops cleanly below 150 MB. `save_transcript` writes the transcript, then `ready`, and only then deletes audio (`deleteAudio`); `record_failure` never deletes. The worker writes `audio/.transcribing` with an attempt count; `recover` (at setup) repairs WAV headers (`repair_wav`), flags crashed recordings `interrupted` and queues them, re-queues an interrupted transcription once, and after two crashes leaves it as `error` for the user. `shutdown` finalizes a live recording on Quit and `RunEvent::Exit`. Reads `cleanTranscript` (default on) and `deleteAudio` from `.privacy.json` via `meetings::preference`.
- `src-tauri/src/recorder.rs` (macOS/Windows only): cpal capture on a dedicated thread (streams aren't `Send` everywhere). Mic from the default input; system audio from a private aggregate device over a global Core Audio process tap on macOS (`mac::SystemTap`, works even when the output device has its own mic) or WASAPI loopback on the default output on Windows. Writer threads downmix, resample to 16 kHz (rubato `Fft`), write i16 WAV with hound and `flush()` every second (crash-safe); they pad silence by wall clock so both tracks stay aligned. `watch` keeps each track on a live device: it reopens a lost stream, one that stopped delivering audio for 3 s (mic, and the macOS tap, which delivers even in silence; not Windows loopback), or one whose system default changed (mic; Windows output), and records a problem ("Microphone disconnected…") or a note ("Microphone changed to …") in `Health`, with device names. macOS mic permission is read and requested through `AVCaptureDevice` (`microphone_permission`, `MIC_DENIED`). `SystemTap::device` waits up to 3 s for Core Audio to publish the aggregate device (each attempt has a unique uid).
- `src-tauri/src/transcribe.rs` (macOS/Windows only): whisper-rs (Metal on macOS) with the bundled `ggml-large-v3-turbo-q5_0.bin` and Silero VAD (`ggml-silero-v6.2.0.bin`), resolved from `BaseDirectory::Resource` (`models/…`, set in `tauri.macos.conf.json` / `tauri.windows.conf.json`) or `resources/models` in debug builds. `status` checks presence and size (pinned in `MODELS`, same pins as `scripts/fetch-models.mjs`); `verified` checks the full SHA-256 once per session before loading. Windows loads the main model from memory (non-ASCII profile paths). Silero VAD finds speech; `chunks` groups it into ≤25 s chunks cut only at real pauses, each transcribed on its own (greedy, `no_context`, language detected once from the longest chunk). Token timestamps split output into timed sentences (also at 1 s word gaps); `align` anchors each start to the speech it overlaps and `mark_pauses` flags sentences after ≥0.5 s silence. A chunk with a decoder loop (`find_loop`: a 2–8-word phrase three times in a row) is retried with beam search, and any remaining repeats are cut (`collapse_loops`, `drop_repeats`). **No initial prompt**: in testing Whisper repeated the meeting name as if spoken.
- `src-tauri/src/transcript.rs` + `cleanup.rs` (pure, all platforms): `merge` labels mic pieces *You* and system pieces *Others*, drops mic echo of the call (`split_echo`, per sentence: the same words in order as call audio playing when the sentence began, with its start within 2.5 s or its end within 1 s; a whole piece under 3 words must match exactly within 0.7 s; when unsure the sentence stays; dropped sentences are kept in `Transcript.echo` for diagnostics only), and joins same-speaker pieces into turns, recording a `breaks` offset where a heard pause and a capital both mark a sentence Whisper left unpunctuated. `markdown` renders `### mm:ss Speaker` turns, clean or verbatim; `Turn::clean` is the clean text. `cleanup::clean` returns delete-only byte ranges (fillers like um/uh/erm/hmm, stutters and repeated 2–3 word phrases, the pause comma before a filler) and `render` applies them, adds full stops at `breaks`, and tidies punctuation/capitalization. It deliberately keeps context-dependent words ("like", "you know", "I mean"), self-corrections ("2… actually 3"; the comma before a number or name stays), numbers and number words, capitalized repeats (names), quoted speech, and a capitalized filler with no pause mid-sentence (a name). "ah"/"eh" count only as comma-wrapped pauses mid-sentence. A capitalized filler mid-line ("…to confirm Hmm, that works") marks a new utterance, so `clean_with_breaks` adds a break there rather than running two sentences together.
- `src-tauri/src/tray.rs` + `app_state.rs`: the macOS menu bar / system tray, a native menu built from `entries` (pure and unit-tested): Start recording… (New meeting… where recording is unavailable), 3 recent meetings, Project submenu, Open QuietNote, Settings…, Quit QuietNote; while recording it's a control surface without recent meetings or projects: "● Recording: title", "Started HH:MM by you · No bot joined", a ⚠ problem line, Stop recording, Open meeting, Open QuietNote, Settings…, and Quit becomes "Stop recording and quit"; while transcribing: a progress line updated in place. It reads recent meetings and projects from disk (`meetings::tray_listing`, metadata only), so it works while the window is hidden, and it never creates meetings itself. Menu actions show the main window and emit `quietnote://open-meeting` / `open-project` / `new-meeting` / `open-settings`, which the Shell handles (ignored while a dialog or capture is open). The Shell reports its context project with `tray_sync`, which also rebuilds the menu. `Shared` (in `app_state.rs`) holds only that project and the quitting flag. The macOS icon is the template image `icons/tray-template.png`; while recording it switches to `tray-recording-template.png` with the elapsed time as the tray title (Windows: `tray-recording.png` and the tooltip). *Start recording…* opens New meeting (after New project if there is none); the tray never starts a recording itself. *Stop recording* calls `capture::stop` directly.
- `src-tauri/src/lib.rs`: upstream Scratch commands (notes CRUD, search, watcher, settings, AI/git tools). Every command, including those in `meetings.rs`, must be registered in the `invoke_handler` here. Tauri v2 permissions go in `src-tauri/capabilities/default.json`.

### On-disk archive
`<app data>/app.quietnote.desktop/meetings/<Project>/<YYYY-MM-DD-slug>/` holds `metadata.json` (duration in **seconds**, status `idle|recording|processing|ready|error`, relative paths), `meeting.md` (title/date/project/duration, then Summary, Decisions, Action items as `- [ ]`, Notes), and `transcript.md`. Recorded meetings also have `audio/mic.wav` + `audio/system.wav` (16 kHz mono) and `transcript.json` (raw turns with cleanup `removed` ranges; `transcript.md` is rendered from it). Transcript text lives **only** in `transcript.md`/`transcript.json`, never in `meeting.md`. `audioPath` is `<Project>/<id>/audio` or null (validated in `bundle`). Optional metadata `interrupted` (recovered after a crash, until dismissed) and `error` (why the last transcription failed) are omitted when unset. `audio/.transcribing` exists only while Whisper runs. The root also holds `.privacy.json`, `.scratch/settings.json` for Scratch compatibility, and `.initialized` in archives from earlier builds that auto-seeded demos. The separate identifier keeps it isolated from a real Scratch install.

### Window lifecycle
Closing the main window (red button, ⌘W) hides it and QuietNote keeps running in the menu bar / tray. `on_window_event` prevents the close in Rust, and the Shell's `onCloseRequested` always calls `preventDefault()` (otherwise Tauri's JS wrapper destroys the window) and saves pending notes. The tray, a Dock click (`RunEvent::Reopen`) or a relaunch restores the same window. Quit QuietNote first finalizes a live recording in Rust, then emits `quietnote://quit-requested`, and the Shell saves pending notes and calls `quietnote_quit`. Rust exits anyway after 3 s. ⌘Q exits immediately, because Tauri can't intercept it; recovery drafts cover unsaved notes, `RunEvent::Exit` finalizes the recording best-effort, and `recover` repairs the audio on the next launch. Standalone preview windows close normally.

### Saving and recovery
Notes are saved through the editor's debounced save. Every keystroke also writes a recovery draft to webview storage, which is retained on save failure and offered for retry/reload. On desktop, `capture::recover` handles interrupted `recording`/`processing` meetings on disk (recovered audio is transcribed; no audio → `error`). In the browser preview they load as `error` in memory ("Needs attention", with Mark as ended). Outside edits raise a "Files changed outside QuietNote" banner with an explicit Refresh; there is no conflict merging.

### Retained upstream Scratch patterns
- `NotesContext` uses a dual context pattern (data/actions separated) for performance.
- Scratch settings: app config at `{APP_DATA}/config.json`, per-folder at `{NOTES_FOLDER}/.scratch/settings.json`.

## Product principles

QuietNote is private and bot-free (see the landing page copy in `../Meetings Application/src/content`). Anything that touches Connections or capture must hold to these:
- Never join a call, add an attendee or use a meeting bot. Call awareness (Zoom/Meet/Teams) may only be detected locally on the Mac.
- No calendar auto-join and no capture before the user presses start. A calendar may pre-fill a meeting, never start one. The tray may open New meeting, but only its Start recording button starts recording.
- Audio and transcription stay on the device. Recording captures only the mic and what the computer plays (a local tap/loopback), never by joining the call. Keep filler cleanup delete-only and keep the raw words available (Verbatim).
- Data leaves the device only on an explicit user action (e.g. Send), and only the minimum (see `issueFor`). Drafts (email, Slack) are reviewed by the user before sending.
- Keys and tokens live in the macOS Keychain, never in webview storage, and never go back to the webview. There is no QuietNote server: future sign-in connectors must use native-app OAuth (RFC 8252: system browser, PKCE, loopback redirect) with tokens kept on the Mac, unlike cloud assistants (e.g. Grok) whose servers hold the tokens.
- Don't claim "fully offline", compliance certifications or end-to-end encryption.

## Coding Conventions

- Clean, minimal code with low technical debt. Don't add commented-out code or TODOs.
- Match the terse style of `src/quietnote/` when editing there (compact one-line helpers, no heavy abstraction).
- Use `React.memo` for expensive list items and `useCallback`/`useMemo` on hot paths.
- Debounce user-triggered operations (auto-save 300ms, search 150ms, file watcher 500ms, git status 1000ms).
- Keep operations async and non-blocking, and surface errors visibly. Corrupt or unreadable archives must show an error rather than silently resetting data.
- Planned privacy settings only record intent. Keep them in the "Planned" group unless they are actually enforced (`cleanTranscript` and `deleteAudio` are enforced when recording is available). Where recording is real the Planned group is hidden, so every setting shown there does something; the browser preview keeps it. Real user meetings must show only data that exists: use empty states ("No summary yet.", "Transcript unavailable."), never generated placeholders.
- Only one cobalt-filled (`.primary`) action per context; everything else uses `.secondary` or `.text-button`. Base element resets in `quietnote.css` use `:where()` so class rules aren't out-specified.
- Preserve Scratch attribution (LICENSE, NOTICE, About/Privacy screens).
