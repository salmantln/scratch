# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

QuietNote is a local-first meeting workspace built on top of **Scratch** (Eric Li's markdown notes app). It is Tauri v2 (Rust) + React 19/TypeScript/Tailwind v4 + TipTap + Tantivy. Meetings are the primary object. On macOS and Windows, capture is real: Rust records the mic and system audio, cancels the call's echo out of the mic track, and transcribes them locally with whisper.cpp, then removes filler words with delete-only rules (the raw words are kept). On macOS the others' voices are also told apart after Stop, and an English live transcript switches to Parakeet (both through sherpa-onnx). The browser preview and Linux keep a **prototype** capture that records nothing. There is no automatic summarization, cloud sync or accounts. Summary suggestions are opt-in: when the user asks, Claude (their own Anthropic key) or a model in Ollama on their computer drafts suggestions from a recorded transcript, and only what the user adds is written. Do not fabricate behavior (e.g. inventing summaries, transcripts or audio). The only runtime network use is user-initiated: Connections (sending action items to Linear or GitHub), summary suggestions with Claude (sending a transcript's text to Anthropic, and the user's notes when enhancing them), and activating or removing an optional license (its key and a fixed device name, to Lemon Squeezy). The speech models are downloaded at build time only.

Upstream Scratch code is retained, not rewritten. The QuietNote shell lives in `src/quietnote/` and `src-tauri/src/meetings.rs` and reuses Scratch's editor, services and Rust commands. `docs/SCRATCH-AUDIT.md` (pre-change audit) and `docs/MODIFIED-FILES.md` (diff manifest vs. upstream) are the reference for what was changed. Keep `docs/MODIFIED-FILES.md` in sync when touching upstream files.

Playwright needs Chromium (`npx playwright install chromium`). Tests run serially (1 worker) against the browser preview in fresh contexts, so they never touch the real desktop archive. Tests J–X drive the desktop recording UI through `mockDesktop(page, fixture)`, a hand-written stand-in for `window.__TAURI_INTERNALS__` that models only the recording commands and events (fixture: meetings, microphone permission, model status, a live recording, a start failure; it also models pause/resume, the microphone list, `window_compact` (`state.compact`) and the live draft, which a test sets in `state.draft` before emitting `quietnote://live-transcript`, as Rust does; `plugin:event|unlisten` removes the listener, so React's development double-mount doesn't leave duplicate handlers). It also stubs `save_file_direct` (last content in `state.saved`), `capture_allow_microphone` (`state.micAnswer`), browser sign-in (`state.signInServices`, `state.pendingSignIn` to resolve or reject, links opened in `state.opened`), the summary commands (`state.summaryKey`, `state.suggestions`), `mcp_agents`/`mcp_agent_set` (`state.agents`), the clipboard plugin (`state.clipboard`) `call_accessibility` (`state.accessibility`) the license commands (`state.license`, `state.licenseAnswer`: a license, or an error string to throw), Export audio (`plugin:dialog|open` answers `state.folder`, null to cancel; `audio_export` calls in `state.exported`), `move_meeting`, and native menus (`plugin:menu|new` keeps the last one in `state.menu`, `popup` counts `state.menus`; `choose(text)` clicks an item; the last saved path is `state.savedPath`). `docs/QA-RECORDING.md` is the manual real-device checklist, `docs/PERFORMANCE.md` the measured numbers, and `docs/WINDOWS.md` the untested Windows risks.

CI (`.github/workflows/ci.yml`) runs `npm run build`, `cargo check` and `cargo clippy -- -D warnings` on Ubuntu (which doesn't compile the recorder), plus clippy on all targets and `cargo test` on macOS with the models cached; lint, typecheck and Playwright must be run locally. The release workflow is manual (`workflow_dispatch`) and creates a draft only; the upstream Scratch update feed is disconnected (update checks are gated on `VITE_QUIETNOTE_UPDATES`).

## Architecture

### Two apps in one bundle
`src/main.tsx` picks the root component from the URL:
- default → `QuietNoteApp` (the meetings shell)
- `?workspace=…` or `?mode=preview` → upstream Scratch `App` (generic Markdown workspace / standalone file preview), lazy-loaded
- `?panel=call&app=…` → `CallPanel` (the call detection panel window, see `calls.rs`), lazy-loaded

The Scratch workspace is reachable from Settings → Local archive → Open Markdown workspace, and links back to QuietNote from its About screen.

### QuietNote shell (`src/quietnote/`)
- `QuietNoteApp.tsx`: single `Shell` component that owns all state (meetings, projects, view, selection, save status, drafts, banners, keyboard shortcuts, window-close handling). `compact` is the Granola-style window beside a call: the call panel's Record (`recordCall`, once the meeting exists) calls `window_compact(true)`, and the shell drops the sidebar, the window bar's navigation (an Open full window button instead), the recording bar and the editor's `[data-format-bar]`, leaving the meeting and its recorder. Open full window, or any view other than the meeting (a shortcut, the tray), calls `window_compact(false)`. Views: home / all / actions / project / meeting / search / settings / people (a remembered `recent` from earlier builds opens Home). The sidebar's *Action items* shows the open count across meetings. The sidebar has no logo or wordmark (they stay in Onboarding, the call panel and About). Its New meeting is `.secondary`, so a screen's one cobalt action is its own (Home's or a meeting's Start recording). Its bottom has *Give feedback* (`storage.giveFeedback` opens a new message to sarl.the.developer@gmail.com in the mail app with only the version and computer filled in; nothing is sent until the user sends it), Connections, Search and Settings. Double-clicking its divider (or Enter on it) switches between icons with labels and icons only (`rail`, remembered as `quietnote.rail`), caught in capture on the `aside` so Scratch's `SidebarResizeHandle` (whose own double-click resets the width) stays unmodified; as icons only the divider doesn't drag. Windows 720px wide or less are always icons only (`narrow`, from `matchMedia`) and have no divider. With no projects and no meetings it renders `Onboarding` instead of the shell. The last view, meeting and tab are remembered in localStorage (`quietnote.place.v1`; a tab from earlier builds, Summary/Decisions/Action items, opens Enhanced). `openMeeting` without a tab uses `model.openingTab`.
- `Onboarding.tsx`: first launch in four screens at most, with Back and step dots (each step keyed, so a click that moves on can't land on the next step's button). Steps are fixed when it opens: hello (Hush, one line, Get started; Explore example meetings), access (macOS, one row per permission not yet given, each with its reason: the microphone while not granted, `capture_allow_microphone`, which asks macOS without recording, denied shows Open System Settings; the calendar while off, which sets `calendar` and asks; Continue leaves either for later, and the recorder's first-run explainer still waits for the mic), and the first project: an optional question (the kind of meeting: picks `noteTemplate`, which `model.templateFor` uses when the title doesn't suggest one, and names the project) above the name (`createProject`); below it, where recording is real, one line says Start recording (⌘⇧R) makes the meeting, in person or on a call. Last, on its own screen, your name (optional, Done or Skip, no Back since the project exists by then: `userName` in `.privacy.json`, also in Settings → Privacy; it puts the user's action items first); the Shell's `finishing` keeps onboarding on screen after it creates the project until then. The illustration when Hush is off is shapes and the app's own labels, never words anyone said. Nothing records here.
- `Hush.tsx`: Hush, the mascot whose face shows what QuietNote is doing (designed in the Paper file "QuietNote — Mascot"). `Hush({ mood, size, look })` draws the Paper shapes as one SVG; moods are real states only: resting, ready, listening, paused, transcribing, suggesting, done, attention, winding. Its styles and keyframes are the "Hush" section at the end of `quietnote.css`: each mood rests on its Paper pose (a mood's last face in `FACES`) and animation only adds to it (sway from the feet, breathing, uneven blinks; the transcribing split, the suggesting bubble, the done hop and check and the attention lean play once, on Apple-style spring curves in `linear()`), and `prefers-reduced-motion` holds the pose. Listening turns the eyes to the side that's talking (`useLook` over `Capture`'s `useLevels`, held 1.2 s), never a scripted glance. Where he is: the Home capture card (instead of the status dot; while transcribing the card is about the transcription, with a progress bar, and `progress` closes the pieces up as the percentage climbs), the call panel (ready; winding during the stop countdown), a meeting's transcribing (with its progress) and problem notices (attention), the drafting notice in `SuggestPanel`, the "Recording saved" / "Transcript ready" banner (transcribing / done; not on Home, where the card has one), resting in empty states (enhanced notes and transcript unless recording or drafting, Action items, People, no meetings, no search results), and the onboarding hello. One per screen is enforced with `HushYield`: the Shell sets it while the banner has Hush, `MeetingDetail` while a notice has one (and leaves out the empty state's while `SuggestPanel` reports `onWorking`), and a yielding `Hush` shows its fallback (the icon or illustration he replaced); on macOS the menu bar icon is Hush too (see `tray.rs`). Settings → Appearance → *Show Hush* (`showHush`, default on, enforced) turns him off: `showHush()` sets it for every `Hush` in a window (the Shell from its preferences, the call panel from `quietnote_preferences` and `quietnote://preferences-changed`, which that command now sends to the call window after a write), and a hidden `Hush` renders its `fallback` (the Home card's status dot, the call panel's `Logo`) or nothing; Onboarding's hello shows its call illustration instead. In the dark theme he's white: `--hush-ink` and `--hush-face` swap (navy eyes, cobalt leaf kept), and the logo's `.logo-ink` paths turn white the same way.
- Theme: Settings → Appearance → *Theme* (System / Light / Dark, `theme` in `.privacy.json`, read with `storage.appearance`, default System). The Shell, once the preferences are read, passes it to Scratch's `ThemeProvider` (`setTheme`, which puts `.dark` on `<html>`, saves it to `.scratch/settings.json` so the Markdown workspace and editor follow, and keeps Scratch's own picker in step) and to the native window (`getCurrentWindow().setTheme`, `core:window:allow-set-theme`; app-wide on macOS, so menus match); `CallPanel` has no ThemeProvider and toggles `.dark` itself from `quietnote_preferences` / `quietnote://preferences-changed`. The dark palette is the "Dark theme" section at the end of `quietnote.css`: Scratch's warm near-black, redefining the `--qn-*` tokens (colours used in rules are tokens, e.g. `--qn-card`, `--qn-well`, `--qn-edge`, `--qn-blue-text` for blue as text) plus a few rule overrides (raised surfaces, avatars, folder art).
- Surfaces (inspired by GatherOS): buttons are pills (`.secondary` a raised card with `--qn-shadow-control`); the recorder dock is a paper pill with a soft shadow (`--qn-shadow-float`), Jump to latest is frosted glass (`--qn-glass`, `--qn-shadow-glass`); toasts are dark pills (`.field-error.floating`, and the editor's Sonner toasts through QuietNote's own `Toasts` with `qn-toast`, outside the shell so its values are literal); durations and the pop curve are `--qn-dur-*` / `--qn-ease-pop`. No design slop: no divider lines between rows or sections (spacing separates them; the sidebar is set apart by its fill), no outlined containers (cards, the search fields and inputs are `--qn-well` fills), no tags or badges (Example, Planned, Built in, Browser preview are plain grey words; participants are names in the meta line), and text is `--qn-ink` or `--qn-muted` only. `--qn-control` is the one fill a step darker than the paper: checkboxes, the off toggle, the progress track and your transcript bubbles (the others' are `--qn-bubble`). Checkboxes are filled squircles drawn as SVG backgrounds (`--qn-check-off` / `-hover` / `-on`, light and dark, in the "Checkboxes" section of `quietnote.css`), since WebKit has no `corner-shape`. Every action-item tick (Home, Action items, People, a meeting's enhanced notes, Last time) goes through the Shell's `toggleItem`, which shows a Sonner toast, "Marked done" or "Reopened", with Undo (`setItem` puts back the state it had, finding the item by its `key`, since items above it may have been removed since; one toast per item, `id` `action:<meeting>:<key>`). In a meeting an item can also be edited (`editItem`) or removed (`removeItem`, a "Removed …" toast whose Undo puts back only that line where it was, `restoreAction`). Action items are shown yours first everywhere they're listed (`model.yoursFirst`, display only: they're still written by position).
- `Library.tsx`: `MeetingList` (rows grouped by day; today's show the time; a row without a status shows its open action-item count; with `move`, right-clicking a row, or the context-menu key, offers *Move to* and the other projects: a native `Menu` on desktop, `MoveMenu` in the browser preview) and `Home`. Home is laid out top to bottom:
  - A capture card built from `CaptureState`, with Hush in the mood it's in: ready, mic denied (Open System Settings), model missing, recording (Open meeting only, on Notes; Stop stays in `RecordingBar`, so there's never a second one), transcribing (titled "Transcribing on this Mac", with a progress bar, the % and the queue; Start recording stays), or prototype (browser preview and Linux: one quiet line without Hush or a fill, so it doesn't lead Home). Start recording calls `quickRecord()` and is Home's one `.primary` (the sidebar's New meeting is `.secondary`), and the prototype's New meeting calls `newMeeting()`. The card's title is 16px, as the section headings.
  - A search field that switches to Search, without a fill until hovered or focused (14px placeholder), so the card leads.
  - Open action items from every meeting, yours first (the first six; *All action items* opens the Action items page). A tick goes through `persist` + `toggleAction`, and a ticked item stays struck through until you leave Home (remembered by `key`). Without a name (`me`) a grey line under the heading says *Add your name* in Settings to see your items first, opening Settings → Privacy (`onName`).

  `ActionItems` (view `'actions'`) is Granola's planned Action Items page: every meeting's items under their meeting (title opens its enhanced notes, date, project; yours first within each), newest first, with an Open / Done switch. A tick goes through `toggleItem` and the item stays where it is until you leave or switch.
  - The ten latest meetings, as `MeetingList` with `grouped={false}` (no day or month headings under Recent), all columns kept.

  Home's lists share one left and right edge with the headings (rows reach past it only with their hover fill, `.home-section :is(.meeting-row, .home-action)`), and both lists' rows are 44px.

  Empty sections are hidden.
- `Dialogs.tsx` (`Modal`, new project, new meeting; with `canRecord` its primary button is "Start recording", which creates the meeting and starts recording it, and "Create meeting" is secondary), `Capture.tsx` and `Settings.tsx` (Privacy / Appearance / Shortcuts / Local archive / About). Shortcuts (`shortcuts.ts`): the main actions' keys (Start recording, New meeting, Search, Settings, the sidebar) are Tauri accelerators in `.privacy.json` (`keyRecord`, `keyNewMeeting`, `keySearch`, `keySettings`, `keySidebar`; unset is the default), read by the Shell's keydown handler through `bound` and `accelerator` (by `KeyboardEvent.code`, so ⌥ doesn't change the key; ⌘ is `CmdOrCtrl`, ⌃ on a Mac is `Control`) and shown with `label`. The others are fixed (`fixed`: ⌘P and ⌘⇧F search, ⌘⇧↩ sidebar, ⌘⇧M source mode, ⌘1–9 projects). `KeyRow` records a key on click (Esc cancels) and `problem` refuses one without ⌘/⌃, one QuietNote or the editor uses, or one another action has. *Start recording from any app* (`globalRecord`, unset ⌃⌥R, '' off; desktop where recording is real) goes through `hotkey_set` first, so a key another app holds is refused with a reason, then is saved. `Capture` is not a dialog: `MeetingDetail` renders it last, as a bar pinned to the bottom of the meeting (region "Recorder", `.recorder-dock`, sticky in `.qn-main`; the article becomes a full-height column via `.docked` so the bar sits at the window's bottom even with short notes) while its meeting is armed to start (the Shell's `capture` `{ id, call }`, dropped on leaving the meeting or when its recording stops) or recording, so Notes and the transcript stay usable above it. It renders `Recorder` when `CaptureState.available` (a view over Rust state). Folded it's a small pill, as in Granola (`Dock`, `align-self: flex-start`): a red dot (grey while paused) with a chevron that opens the details drawer (folded unless opened before, `quietnote.drawer.v1`), the recorded time (`model.recorded`: `recordedMs` plus the time since `resumedAt`, which is null while paused), a round filled Pause and a dark Stop pill labelled Stop (Resume while paused is the same button, the one primary, labelled, its bars morphing into a play triangle: `MorphIcon` in `Icon.tsx`, three strokes per icon moved by CSS transforms; the details chevron turns the same way). "Recording" is screen-reader only (the dot says it); Paused and Stopping… show. It widens into a card (`.wide`) when the drawer is open or an alert or note shows. The drawer holds a caption pointing to the live draft ("Live draft on the Transcript tab": the draft is shown there only, so the notes keep the room while recording) and the consent line ("Let everyone know you're recording.") with Copy message (`consentMessage`, to paste into the call's chat; QuietNote never types into the call app); with it open, the line also has the microphone picker (`MicPicker`: System default or a named device from `capture_devices`; `capture_set_device` switches a running recording and keeps the choice). There are no per-track meters; silent tracks show as alerts. Device problems, notes and silent-track hints with Open System Settings sit between drawer and line. While the mic permission is `undetermined` an in-app start expands into the first-run explainer with Cancel / Start recording instead of starting automatically, so the explanation comes before the macOS prompt; the call panel's Record (`autoStart` `'call'`) starts at once, as in Granola, and macOS asks by itself. A `mic-denied` start failure shows Open System Settings and Try again. Otherwise it renders `Prototype` (browser preview and Linux: `idle` → `recording` → `ready` from the meeting's metadata, records nothing, no simulated processing). There's no "ended" step: after Stop the bar goes and the meeting's transcribing notice takes over. `LiveTranscript` shows `capture_live_transcript` then `quietnote://live-transcript` for its meeting as bubbles (You right, Others left, clean or verbatim), follows the newest unless scrolled back (Jump to latest), and shows dots for a side whose level was loud in the last 1.5 s (`useListening`, read by `MeetingDetail` for the Transcript tab): never invented words.
- `model.ts`: `Meeting = { metadata, markdown, transcript }` plus pure helpers for reading and writing `##` sections of `meeting.md` (`section`, `replaceSection`, `toggleAction`, `appendAction`), parsing (`actionItems` with `Owner — task`; each item's `key` is its line's text, owner included and link left out, and which copy it is when lines read the same, so ticks, Undo and the struck-through lists find it after other items are removed; `editAction` changes only the task text, `removeAction`/`actionLine`/`restoreAction` take a line out and put it back; `mine(owner, name)`: the owner is "You" or the user's full or first name, never an item without an owner; `transcriptTurns` from `### mm:ss Speaker`, `enhancedNotes`: the Summary section plus an earlier build's Decisions section as a `### Decisions` heading, so it's never hidden), where a meeting opens (`openingTab`: Enhanced once it has enhanced notes, action items or a transcript, else Notes), and search context (`searchMeeting` returns the matching tab, Enhanced / Notes / Transcript, and a snippet). The **Notes** section is always last and consumes the rest of the file, so headings inside notes survive.
- `storage.ts`: persistence facade that branches on `isTauri()`:
  - **Desktop**: `invoke()` calls into `meetings.rs` for archive load/create/metadata/preferences. Markdown is saved with Scratch's `saveFileDirect`. `moveMeeting` notes the old and new paths as own writes, then `move_meeting`. On load it points Scratch's notes folder at the archive root and starts its file watcher, so Tantivy search (`indexedSearch`) works over meeting files.
  - **Browser preview**: everything goes to `localStorage` (`quietnote.preview.archive.v1`, `quietnote.preview.projects.v1`, `quietnote.privacy`). It never migrates into the desktop app.
  - Desktop saves are recorded in `ownWrites` so the watcher's `file-change` events for QuietNote's own writes don't trigger the "Files changed outside QuietNote" prompt. Rust's `transcript.md` writes are recorded the same way when `quietnote://meeting-changed` arrives.
  - Recording: `captureStatus`/`captureStart` (rejects with `CaptureFailure { code: 'mic-denied' | 'disk' | 'failed', message }`)/`captureStop`/`capturePause`/`captureResume` (rejects like start)/`captureDevices`/`setCaptureDevice`/`liveTranscript`/`transcribe`/`transcriptData`/`renderTranscripts`/`revealAudio`/`openPrivacySettings`. The Shell keeps `live: CaptureState` from `quietnote://capture-state` and upserts meetings from `quietnote://meeting-changed` (metadata, a finished transcript, or a problem shown as a banner). While recording, `RecordingBar` in the window header shows Recording or Paused, the title, the recorded time (`model.clock`, the same format as the tray), Resume while paused, and Stop in every view except the recording meeting itself, where the recorder bar has the only Stop. The tray's Pause/Resume/Stop run in Rust; a failure arrives as `quietnote://capture-problem` and shows as a banner. However a recording stops (recorder, bar, tray, low disk), a "Recording saved" banner (then "Transcript ready") with Open meeting says where it went, unless that meeting is open. A banner lists meetings with `interrupted` ("Recovered recording").
- `MeetingDetail.tsx`: two tabs, Notes and Transcript, as in Granola. `MeetingTab` is `'Enhanced' | 'Notes' | 'Transcript'`: the Notes tab has an *Enhanced notes* / *My notes* switch (group "Notes view") and comes back to whichever was shown last. Enhanced notes are the meeting's action items (`.note-actions`: checklist, yours first, *Add an action item*, Send to…; `ActionRow`: pressing an item's text edits it, Enter saves, Escape keeps it, empty text changes nothing; its × (on hover or focus) removes it), leading the note once there are any and after it until then, then `enhancedNotes` through `model.summaryBlocks`, with `SuggestPanel` on top for a recorded meeting; without enhanced notes it says *No enhanced notes yet.* and how to get them; for a recorded meeting that's highlighting what matters in My notes (⌘⇧H, the editor's TipTap Highlight, saved as `==text==`) and enhancing, with `EnhanceDemo`: a card labelled Example (never the meeting's words) that plays once, the first time (`quietnote.enhance-demo.v1`: mark, an added grey line with its time, a suggested action item), then shows its last frame, as it does with Reduce Motion. There are no decisions: new meetings have no Decisions section and nothing adds to one. My notes lazy-loads Scratch's real `components/editor/Editor` inside `NotesBoundary`, so an editor failure shows "Notes couldn't open." with Reload instead of blanking the window; `Crashed` in `QuietNoteApp.tsx` does the same for the whole shell. The summary and action items are parsed from Markdown, not stored separately. An idle meeting's Start recording is its primary action, starts at once and switches to Notes (there's no confirm step; the first-run explainer still waits); New meeting's Start recording also opens on Notes. A recorded `ready` meeting has a quiet *Record more* text button (red dot) that does the same, recording more into it. The meeting is one 720px column (header, tabs, notes, transcript, the editor's text and toolbar) with one type scale: title 26px, section headings 16px (in My notes too), notes and transcript text 15px/24px, action items 14px, owners and timestamps 12px. - `src-tauri/src/capture.rs`: the recording/transcription lifecycle and its commands (`capture_status`, `capture_start`, `capture_stop`, `capture_pause`, `capture_resume`, `capture_devices`, `capture_set_device`, `capture_live_transcript`, `transcribe_meeting`, `transcript_data`, `render_transcripts`, `open_privacy_settings`). Managed state `Capture` holds the one live `Session` and a FIFO transcription queue with a single worker thread; `claim()` allows one recording at a time. A `Session` counts recorded time as `recorded` (before the current run) plus the wall clock since `wall`, so pauses don't count and window and tray agree; its `Health` outlives each run of the recorder. `pause` stops the recorder (finalizing the WAVs and releasing the mic) while the meeting stays `recording`; `resume` restarts it appending to the same files (both under the session lock, so a stop can't land halfway). Starting a `ready` meeting records more of it (only if it has `transcript.json` or an empty `transcript.md`, so a written transcript is never replaced): kept audio is appended to, otherwise new files are made, and `metadata.resume` (`resume_point`: `atMs` after the earlier recording and its last words, `sample` where the new audio starts in the files) makes `process` transcribe only the new part and add it with `transcript::append`; `save_transcript` clears it and recovery accounts for it. `LiveText` (off/loading/on/failed) is reported per recording; `begin` spawns `live::spawn` when the `liveTranscript` preference (default on) and the model allow, and `Capture.draft` keeps the latest `Draft` until the worker finishes that meeting. `State` also carries the microphone permission and the model status (ready/missing/damaged). Rust owns a meeting's status while it records or transcribes (`owns`; `save_meeting_metadata` refuses those meetings). Every step that looks a meeting's folder up (`meetings::find`) and then reads or writes its files holds `meetings::files()`, the lock `move_meeting` holds, so a move lands wholly before or after it; the worker looks the folder up again for each track (`track`, through `transcribe::run`'s reader), never keeping a path across a step. Never take `session` or `jobs` (`owns`, `publish`, `set_progress`) while holding it: `resume` takes `session` then `files`: `idle` → `recording` (audio folder set) → `processing` → `ready`, or `error` with the audio kept and the reason in `metadata.error`. Start is refused below 1 GB free; the ticker warns below 1 GB and stops cleanly below 150 MB. `save_transcript` writes the transcript, then `ready`, and only then deletes audio (`deleteAudio`); `record_failure` never deletes. The worker writes `audio/.transcribing` with an attempt count; `recover` (at setup) repairs WAV headers (`repair_wav`), flags crashed recordings `interrupted` and queues them, re-queues an interrupted transcription once, and after two crashes leaves it as `error` for the user. `shutdown` finalizes a live recording on Quit and `RunEvent::Exit`. `pause_on_sleep` (macOS, `NSWorkspaceWillSleepNotification`) pauses a running recording before the Mac sleeps and sets a note; it waits for Resume. `pause_media` sends MediaRemote's pause command (`mac::pause_media`, private framework loaded with `CFBundle`; pause never starts playback) when recording starts or resumes. `process` transcribes, then on macOS (`SEPARATES`) labels the others' pieces by voice (`separate` → `speakers`) before merging, with transcription shown as 90% of the progress; a failure there only leaves "Others". Reads `cleanTranscript` (default on), `deleteAudio`, `liveTranscript` (default on), `echoCancellation` (default on), `separateSpeakers` (default on) and `pauseMedia` (default on) from `.privacy.json` via `meetings::preference`, and `inputDevice` via `meetings::preference_str` (`meetings::set_preference` writes it).
- `src-tauri/src/protect.rs`: how the Mac protects the archive; QuietNote itself encrypts only recordings (`sealed.rs`). `disk_encryption` reads `fdesetup status` (`filevault`, pure: on/off/encrypting/decrypting/unknown; "unavailable" off macOS), shown in Settings → Privacy as *Encrypted by FileVault* or *FileVault is off* with Open System Settings (`open_privacy_settings('fileVault')`), re-read on focus. Recordings are kept out of Time Machine (`NSURLIsExcludedFromBackupKey` on each `audio/` folder, which stays with the folder) unless `backupAudio` (default off, Settings → *Back up recordings with Time Machine*, macOS): `recording` marks the folder in `capture::begin`, `sync` (at setup and after `quietnote_preferences` writes, only when the value changed) re-marks every meeting's. Transcripts and notes are backed up as before.
- `src-tauri/src/sealed.rs` (all platforms; the key only on macOS): recordings encrypted at rest while `encryptAudio` is on (default on, macOS, Settings → Privacy → *Encrypt recordings*). A track is `mic.qna` / `system.qna`: a 26-byte header (`QNA1`, rate, channels, random file id), then AES-256-GCM frames (`ring`) of `len | nonce | ciphertext | tag`, about a second each (sealed early at 1 MB, so padding a long gap stays in bounds), each with the header and its index as associated data, so frames can't be changed, reordered or moved between files. The key is random, one per user, made on the first encrypted recording and kept in the login Keychain (`connectors::keychain`, account `audio`, base64), which Time Machine and Migration Assistant carry with the Mac, unlike Granola's device-only item; an unreadable stored key is never replaced. `key` caches it; `path` finds a track (`.qna`, else `.wav`); `length`/`duration` read the frame lengths only, so recovery and resuming never need the key; a partial last frame (a crash) is ignored, and `Writer::append` cuts it off before continuing. `samples`/`read` decrypt for `transcribe::samples` (the one reader) and `audio_export`. `capture::audio_key` gives the recorder the key for new tracks while `encryptAudio` is on, and always for tracks already encrypted (refused with `MISSING_KEY` without it); if the Keychain fails, new audio is recorded as WAV with a note saying so. A recording keeps the format it started with when it's paused, resumed or recorded more of. WAVs from earlier builds are read and exported as before. `audio_export(meetingId, folder)` writes a WAV per track into a folder the user picks each time (the dialog plugin's folder picker, from *Export audio…* in a meeting, which replaced Show audio), `<id> mic.wav` or `… 2.wav`, never replacing a file, and refused while `Capture::owns` the meeting.
- `src-tauri/src/recorder.rs` (macOS/Windows only): cpal capture on a dedicated thread (streams aren't `Send` everywhere). `start(dir, health, append, cancel_echo, key)`: each track is a `Track` (a hound WAV, or a `sealed::Writer` when there's a key), opened by `open_track`: with `append` (resume) the file already there as it was recorded, otherwise a new `.qna` with a key and a `.wav` without; `even_tracks` first pads the shorter track with silence. Mic from the device chosen by name (`Health::with_mic` / `choose_mic`, which reopens a running stream; listed by `input_devices`, without QuietNote's own `SYSTEM_DEVICE`), or the default input when none is chosen or it isn't connected (a note says so, and it switches back when it reappears); system audio from a private aggregate device over a global Core Audio process tap on macOS (`mac::SystemTap`, works even when the output device has its own mic) or WASAPI loopback on the default output on Windows. Writer threads downmix, resample to 16 kHz (rubato `Fft`), write i16 samples and `flush()` every second (crash-safe: a WAV's header is rewritten, an encrypted track seals the second as a frame); they pad silence by wall clock so both tracks stay aligned. With `cancel_echo` (the `echoCancellation` preference, default on) the system writer shares what it writes (`Played`, by track position) and the mic writer runs each 4 ms block through `Canceller`: WebRTC's AEC3 `BlockProcessor` from `sonora-aec3` (pure Rust) after Sonora's high-pass filter, with the call audio of the same position as reference, waiting up to 200 ms for it. Only the linear filter's output is written (AEC3's suppressor muted the user under continuous call audio), and a block that would come out louder than it went in is kept as it was; `written` counts what the canceller still holds, so padding stays on the clock. While the live transcript follows (`Health::follow`), every sample written (padding included) is also kept in `Health`'s feed for `take_feed`, so the live timeline is the file's. `watch` keeps each track on a live device: it reopens a lost stream, one that stopped delivering audio for 3 s (mic, and the macOS tap, which delivers even in silence; not Windows loopback), or one whose system default changed (mic; Windows output), and records a problem ("Microphone disconnected…") or a note ("Microphone changed to …") in `Health`, with device names. macOS mic permission is read and requested through `AVCaptureDevice` (`microphone_permission`, `MIC_DENIED`). `SystemTap::device` waits up to 3 s for Core Audio to publish the aggregate device (each attempt has a unique uid).
- `src-tauri/src/transcribe.rs` (macOS/Windows only): whisper-rs (Metal on macOS) with the bundled `ggml-large-v3-turbo-q5_0.bin` and Silero VAD (`ggml-silero-v6.2.0.bin`), resolved from `BaseDirectory::Resource` (`models/…`, set in `tauri.macos.conf.json` / `tauri.windows.conf.json`) or `resources/models` in debug builds. `status` checks presence and size (pinned in `MODELS`, same pins as `scripts/fetch-models.mjs`); `verified` checks the full SHA-256 once per session before loading. Windows loads the main model from memory (non-ASCII profile paths). Silero VAD finds speech; `chunks` groups it into ≤25 s chunks cut only at real pauses, each transcribed on its own (greedy, `no_context`, language detected once from the longest chunk). Token timestamps split output into timed sentences (also at 1 s word gaps); `align` anchors each start to the speech it overlaps and `mark_pauses` flags sentences after ≥0.5 s silence. A chunk with a decoder loop (`find_loop`: a 2–8-word phrase three times in a row) is retried with beam search, and any remaining repeats are cut (`collapse_loops`, `drop_repeats`). **No initial prompt**: in testing Whisper repeated the meeting name as if spoken. `run` can start at a sample and offset the times (a resumed recording). The per-chunk step (`transcribe_span`, `speech`, `language`) is shared with `Engine` (macOS), which keeps the model, a state and the VAD loaded for the live transcript and uses 4 threads.
- `src-tauri/src/live.rs` (macOS only): the live transcript. `spawn` turns on the recorder's feed and runs a thread that loads the `Detector` (Silero VAD) and Whisper's `Engine` (the recording has already started) and every 3 s takes the feed, finds speech per track, and transcribes the chunks `ready` says are finished (followed by 600 ms of silence, ≤8 s chunks, forced after 25 s, or everything when paused), then merges all pieces so far with `transcript::merge` and sends the turns (`capture::set_draft` → `quietnote://live-transcript`). - `src-tauri/src/transcript.rs` + `cleanup.rs` (pure, all platforms): `merge` labels mic pieces *You* and system pieces *Others* (or their `Piece.speaker` from `speakers`), drops mic echo of the call (`split_echo`, per sentence: the same words in order as call audio playing when the sentence began, with its start within 2.5 s or its end within 1 s; a whole piece under 3 words must match exactly within 0.7 s; when unsure the sentence stays; dropped sentences are kept in `Transcript.echo` for diagnostics only), and joins same-speaker pieces into turns (a new turn after a 2 s gap, or once a turn has run 15 s, so long talking reads as timed paragraphs), recording a `breaks` offset where a heard pause and a capital both mark a sentence Whisper left unpunctuated. `markdown` renders `### mm:ss Speaker` turns, clean or verbatim; `Turn::clean` is the clean text. `cleanup::clean` returns delete-only byte ranges (fillers like um/uh/erm/hmm, stutters and repeated 2–3 word phrases, the pause comma before a filler) and `render` applies them, adds full stops at `breaks`, and tidies punctuation/capitalization. It deliberately keeps context-dependent words ("like", "you know", "I mean"), self-corrections ("2… actually 3"; the comma before a number or name stays), numbers and number words, capitalized repeats (names), quoted speech, and a capitalized filler with no pause mid-sentence (a name). "ah"/"eh" count only as comma-wrapped pauses mid-sentence. A capitalized filler mid-line ("…to confirm Hmm, that works") marks a new utterance, so `clean_with_breaks` adds a break there rather than running two sentences together.
- `src-tauri/src/templates.rs` (all platforms): note templates for enhanced notes, a name and sections (`heading`, what goes there). Six are built in (General, 1:1, Standup, Sales call, User interview, Project kickoff); the user's own are Markdown files in `<archive>/.templates` (`# Name`, then `## Heading` + description), replacing a built-in of the same name. `.templates` is never a project (`safe_component` rejects the dot). `note_templates` lists them; `open_templates` creates the folder with an example and opens it.
- Names (`summarize.rs` `meeting_names`, `capture.rs` `transcript_rename_speaker`): `meeting_names` sends the transcript lines and the invited people's names (`attendees` without `me`, else `participants`) with `NAMES_INSTRUCTIONS`; `ground_names` keeps a title of at most 8 words / 60 characters, and a voice's name only if the label is an unnamed voice in the turns ("Speaker N", or "Others" when exactly one other person was invited), the cited line is in the transcript, and the name is said there or invited; one name per voice and voice per name. `transcript_rename_speaker` relabels a voice in `transcript.json` (a name another voice has merges them), re-renders `transcript.md`, emits `meeting-changed`, and is refused while `Capture::owns`. The words never change.
- `src-tauri/src/summarize.rs` (all platforms): `notes_enhance` sends the template, the user's Notes section (`notes_of`), what they highlighted in it (`highlighted`: `==text==` within a line, listed under "They highlighted", which the instructions put first in their section) and the transcript lines through `ask` (the same provider dispatch as suggestions) with `NOTES_INSTRUCTIONS` (the notes lead; little or no notes means the transcript does) and `notes_schema`; `ground_notes` keeps a line only if it quotes the notes (`source` "notes") or cites a turn exactly (`source` "transcript"), under the template's own headings in its order, once each, counting the rest as dropped. Summary suggestions: `summary_suggest` reads `transcript.json`, sends the clean turns as `[mm:ss] Speaker: text` lines (nothing else: no audio, notes or title) to Anthropic (`claude-opus-5-5`, structured output `output_config.format`, `fallbacks: "default"`) or Ollama (`127.0.0.1:11434/api/chat`, `format` schema, `num_ctx` sized to the transcript and capped at 32k: longer meetings are refused, never truncated), then `ground` keeps an action item only if its `at` is a turn's timestamp and its `quote` is in that turn's words, keeps an owner only if it's *You* or a name said in the transcript, and drops duplicates, counting what it dropped. It writes nothing. The Anthropic key is verified (`GET /v1/models`) and kept in the Keychain through `connectors::keychain` (service `anthropic`); `summary_key_status` returns only whether it exists. Provider and Ollama model are `summaryProvider` / `ollamaModel` in `.privacy.json`.
- Recordings that stop by themselves (`capture.rs`): `Session.ending` (`Ending { reason, at }`) is a countdown. `call_ended` (from `calls::Ender`, when the call app that held the mic during the recording has let go of it for 6 s) starts one of 60 s; the ticker's `count_down` starts one of 2 min after 15 min with nothing heard (`Health::quiet_for`, peaks ≥ 0.02 on either track; `clear` and `keep` restart it), cancels that one on any sound, and `stop`s with a reason once a countdown has run out and both tracks have been quiet for 10 s (`step`, pure and tested). `capture_keep` (also the tray's *Keep recording*) cancels it. `Live.ending` (`reason`, `stopsAt`) drives the recorder alert, `RecordingBar` and the tray line; `calls::ending_panel` shows the call panel, which then shows the countdown (it reads `capture_status`/`capture-state`; 72 pt tall instead of 56 so the reason can wrap) with Stop and Keep recording. Pausing clears it.
- `src-tauri/src/calls.rs`: call detection (macOS only; `calls::available()`, reported as `CaptureState.detectsCalls`). A thread polls Core Audio's process objects every 2 s (`kAudioProcessPropertyIsRunningInput`, own pid skipped) and maps bundle ids to call apps with `app_name` (an allowlist incl. helpers: Zoom, Teams, FaceTime, Slack, Webex, Discord, WhatsApp, Chrome/Safari/Arc/Firefox/Edge/Brave; anything else is never offered). With `confirmMeetings` (default off, Settings → "Recognize meetings in browsers", which asks for Accessibility through `call_accessibility`) and Accessibility allowed, a browser counts only while `service(ax::titles(…))` finds a meeting in a window or tab (Google Meet, Teams, Zoom web, Webex, Whereby, Jitsi), and is offered under the service's name; without permission nothing changes. `Detector::step` (pure, unit-tested) offers an app after it holds the mic 3 s, once per stretch of mic use, never while recording (and not again after stopping mid-call), and hides when the app lets go. The offer is the `call` window: undecorated, always on top, not focused on show, never activating QuietNote when clicked (`_setPreventsActivation`, so dismissing it leaves the call in front), rounded via the NSWindow layer, over full-screen apps, top right of the pointer's screen (`src/quietnote/CallPanel.tsx`, capability `capabilities/call.json`). `call_record` shows the main window and emits `quietnote://record-call` (app name), which the Shell turns into a `"<App> call"` meeting that starts recording through `createMeeting(…, true)` (ignored while a dialog is open; opens the recording meeting if one is live; New meeting if there's no project). `call_mute` appends to `mutedCallApps` in `.privacy.json` and emits `quietnote://preferences-changed`; `detectCalls` (default on) turns it off. It never starts capture itself.
- `src-tauri/src/compact.rs`: `window_compact` turns the main window into a 420 pt column at the right of the work area of the screen under the pointer (where the panel was clicked: beside the call), lowering the minimum size, and saves the full frame (outer position, inner size) in managed `Compact`; `false` restores it (or 1280×850 centred). `column` is pure and unit-tested.
- `src-tauri/src/hotkey.rs`: Start recording from any app (macOS, Windows), with `tauri-plugin-global-shortcut` (added in `init` at setup). `sync` (at setup and after `quietnote_preferences` writes) registers `globalRecord` (`wanted`: unset is `DEFAULT` ⌃⌥R, '' is off); a press shows the main window and emits `quietnote://record-now`, the tray's path. `hotkey_set` registers the new key before letting go of the old one, so a refused key keeps the old one working. It never records by itself.
- `src-tauri/src/login.rs`: Open at login (macOS). `sync` (at setup and after `quietnote_preferences` writes) registers or unregisters the app as the user's login item with `SMAppService.mainAppService` (System Settings → General → Login Items, as Granola does; takes effect at once) to match `openAtLogin` (default on), only for a release build inside a `.app` bundle, so dev builds never register `target/`. It removes the LaunchAgent earlier builds wrote (`~/Library/LaunchAgents/app.quietnote.desktop.plist`). A `login-item` file in the app data folder records that QuietNote registered itself, so a login item the user removed in System Settings isn't added back: `step` (pure, tested) then turns `openAtLogin` off and emits `quietnote://preferences-changed` to the Shell. Without it QuietNote isn't running and no call is noticed. A login launch (`background`: the open-application Apple event's `keyAELaunchedAsLogInItem`, read during setup, or `--background` from the old LaunchAgent) keeps the main window hidden.
- `src-tauri/src/tray.rs` + `app_state.rs`: the macOS menu bar / system tray, a native menu built from `entries` (pure and unit-tested): Start recording (New meeting… where recording is unavailable), 3 recent meetings, Project submenu, Open QuietNote, Settings…, Quit QuietNote; while recording it's a control surface without recent meetings or projects: "● Recording: title" ("❙❙ Paused: title"), "Started HH:MM", a ⚠ problem line, Pause recording (Resume recording), Stop recording, Open meeting, Open QuietNote, Settings…, and Quit becomes "Stop recording and quit"; while transcribing: a progress line updated in place. It reads recent meetings and projects from disk (`meetings::tray_listing`, metadata only), so it works while the window is hidden, and it never creates meetings itself. Menu actions show the main window and emit `quietnote://open-meeting` / `open-project` / `new-meeting` / `record-now` / `open-settings`, which the Shell handles (ignored while a dialog or capture is open). The Shell reports its context project with `tray_sync`, which also rebuilds the menu. `Shared` (in `app_state.rs`) holds only that project and the quitting flag. The macOS icon is a template image of Hush (drawn from the Paper file's menu bar tile, 36 px) whose face is `mood` (pure, tested) of the capture state, set on every `refresh`: `icons/tray-template.png` (resting), `tray-recording-template.png` (recording), `tray-paused-template.png`, `tray-winding-template.png` (the stop countdown), `tray-attention-template.png` (a recording problem), `tray-transcribing-template.png` (from Stop until the transcript is saved, queue included) and `tray-done-template.png` for 4 s after a transcript is saved (`transcribed`), with the recorded time as the tray title, prefixed ❙❙ while paused (`recording_tick`, title only; the ticker clears it again if Stop landed while it drew); with `showHush` off it's the logo (`tray-logo-template.png`, `tray-logo-recording-template.png` while recording). `STATE` and `HUSH` hold what's drawn, and `restyle` redraws after `quietnote_preferences` saves (Windows: `tray-recording.png` and the tooltip, unchanged by `showHush`). *Start recording* emits `record-now`, and the Shell's `quickRecord` starts it (New project first if there is none). The tray never starts a recording unless that item is clicked. *Stop recording*, *Pause recording* and *Resume recording* call `capture` directly.
- `src-tauri/src/lib.rs`: upstream Scratch commands (notes CRUD, search, watcher, settings, AI/git tools). Every command, including those in `meetings.rs`, must be registered in the `invoke_handler` here. Tauri v2 permissions go in `src-tauri/capabilities/default.json`.

### On-disk archive
`<app data>/app.quietnote.desktop/meetings/<Project>/<YYYY-MM-DD-slug>/` holds `metadata.json` (duration in **seconds**, status `idle|recording|processing|ready|error`, relative paths), `meeting.md` (title/date/project/duration, then Summary, Action items as `- [ ]`, Notes; meetings from earlier builds may also have a Decisions section, shown in the enhanced notes), and `transcript.md`. Recorded meetings also have `audio/mic.qna` (echo-cancelled unless turned off) + `audio/system.qna` (16 kHz mono, encrypted, see `sealed.rs`; `.wav` from earlier builds or with *Encrypt recordings* off) and `transcript.json` (raw turns with cleanup `removed` ranges, speakers "You", "Others" or "Speaker N"; `transcript.md` is rendered from it). Transcript text lives **only** in `transcript.md`/`transcript.json`, never in `meeting.md`. `audioPath` is `<Project>/<id>/audio` or null (validated in `bundle`). Optional metadata `interrupted` (recovered after a crash, until dismissed), `error` (why the last transcription failed), `resume` (`{ atMs, sample }` while recording more of a finished meeting is being recorded or transcribed), `calendarEvent`/`calendarSeries` (the event occurrence and series it was made from) and `attendees` (`[{ name, email, me? }]` from the invite) are omitted when unset. `audio/.transcribing` exists only while Whisper runs. The root also holds `.privacy.json`, `.scratch/settings.json` for Scratch compatibility, and `.initialized` in archives from earlier builds that auto-seeded demos. The separate identifier keeps it isolated from a real Scratch install.

### Window lifecycle
Closing the main window (red button, ⌘W) hides it and QuietNote keeps running in the menu bar / tray. On macOS it's then a menu bar app: `tray::sync_dock` sets the `Accessory` activation policy (no Dock icon or ⌘-Tab, like Granola) whenever no window but the call panel is visible, and `Regular` again when one gains focus (from `on_window_event`: the close, `Focused(true)`, `Destroyed`, and the `--background` launch). `on_window_event` prevents the close in Rust, and the Shell's `onCloseRequested` always calls `preventDefault()` (otherwise Tauri's JS wrapper destroys the window) and saves pending notes. The tray, a Dock click (`RunEvent::Reopen`) or a relaunch restores the same window. Opened at login (see `login.rs`), it starts in the menu bar with the window hidden. Quit QuietNote first finalizes a live recording in Rust, then emits `quietnote://quit-requested`, and the Shell saves pending notes and calls `quietnote_quit`. Rust exits anyway after 3 s. On macOS ⌘Q doesn't quit, as in Granola: `tray::app_menu` replaces the default app menu's Quit with *Close to Menu Bar* (⌘Q, `close_to_menu_bar`: hides the main window, closes the others except the call panel; a recording carries on) and *Quit QuietNote*, the same as the tray's (only when the tray icon exists, otherwise the default Quit stays). Other exits (the Dock's Quit, logging out, Windows/Linux Quit) exit immediately; recovery drafts cover unsaved notes, `RunEvent::Exit` finalizes the recording best-effort, and `recover` repairs the audio on the next launch. Standalone preview windows close normally.

### Saving and recovery
Notes are saved through the editor's debounced save. Every keystroke also writes a recovery draft to webview storage, which is retained on save failure and offered for retry/reload. On desktop, `capture::recover` handles interrupted `recording`/`processing` meetings on disk (recovered audio is transcribed; no audio → `error`). In the browser preview they load as `error` in memory ("Needs attention", with Mark as ended). Outside edits raise a "Files changed outside QuietNote" banner with an explicit Refresh; there is no conflict merging.

### Retained upstream Scratch patterns
- `NotesContext` uses a dual context pattern (data/actions separated) for performance.
- Scratch settings: app config at `{APP_DATA}/config.json`, per-folder at `{NOTES_FOLDER}/.scratch/settings.json`.

## Product principles

QuietNote is private and bot-free (see the landing page copy in `../Meetings Application/src/content`). Anything that touches Connections or capture must hold to these:
- Never join a call, add an attendee or use a meeting bot. Call awareness (Zoom/Meet/Teams) may only be detected locally on the Mac.
- No calendar auto-join and no capture before the user presses start. A calendar may pre-fill a meeting, never start one. The calendar is read through EventKit on the Mac, only while turned on, and never changed. Recording starts only from a Start recording the user presses (Home, the tray, its in-app shortcut or the one from any app, a meeting, New meeting, the call panel). The calendar only names the meeting.
- Audio and transcription stay on the device. Summary suggestions send a transcript's text (only the text; enhancing notes adds the user's notes and the template, naming adds the invited people's names), only when the user asks for that meeting, and only to the provider they chose with their own key; local Ollama sends nothing. Generated items are suggestions until the user adds them, every action item must cite the transcript, and every enhanced-notes line must quote the transcript or the user's notes. A recording may stop by itself (the call ended, a long silence), but only after a visible countdown the user can cancel; it never starts by itself. Recording captures only the mic and what the computer plays (a local tap/loopback), never by joining the call. Keep filler cleanup delete-only and keep the raw words available (Verbatim).
- Data leaves the device only on an explicit user action (e.g. Send), and only the minimum (see `issueFor`; a license sends only its key and a fixed device name). Drafts (email, Slack) are reviewed by the user before sending.
- Keys and tokens live in the macOS Keychain, never in webview storage, and never go back to the webview. There is no QuietNote server: sign-in connectors use native-app OAuth (RFC 8252: system browser, PKCE, loopback redirect, or a device flow where the browser flow needs a secret; `oauth.rs`) with tokens kept on the Mac, unlike cloud assistants (e.g. Grok) whose servers hold the tokens.
- Don't claim "fully offline", compliance certifications or end-to-end encryption.

## Coding Conventions

- Clean, minimal code with low technical debt. Don't add commented-out code or TODOs.
- Match the terse style of `src/quietnote/` when editing there (compact one-line helpers, no heavy abstraction).
- Use `React.memo` for expensive list items and `useCallback`/`useMemo` on hot paths.
- Debounce user-triggered operations (auto-save 300ms, search 150ms, file watcher 500ms, git status 1000ms).
- Keep operations async and non-blocking, and surface errors visibly. Corrupt or unreadable archives must show an error rather than silently resetting data.
- Planned privacy settings only record intent. Keep them in the "Planned" group unless they are actually enforced (`cleanTranscript`, `deleteAudio`, `liveTranscript`, `echoCancellation`, `separateSpeakers`, `pauseMedia`, `confirmMeetings`, `calendar`, `openAtLogin`, `backupAudio` and `encryptAudio` are enforced when recording is available; the last seven are macOS only). Where recording is real the Planned group is hidden, so every setting shown there does something; the browser preview keeps it. Real user meetings must show only data that exists: use empty states ("No summary yet.", "Transcript unavailable."), never generated placeholders.
- Only one cobalt-filled (`.primary`) action per context; everything else uses `.secondary` or `.text-button`. Base element resets in `quietnote.css` use `:where()` so class rules aren't out-specified.
- QuietNote is AGPL-3.0 (`LICENSE`, the verbatim license text). Scratch isn't credited in the app's screens, but its MIT copyright notice must ship: it's in `NOTICE`, and both files are bundled in the app (`bundle.resources` in `tauri.conf.json`).
