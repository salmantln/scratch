# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

QuietNote is a local-first meeting workspace built on top of **Scratch** (Eric Li's markdown notes app). It is Tauri v2 (Rust) + React 19/TypeScript/Tailwind v4 + TipTap + Tantivy. Meetings are the primary object. On macOS and Windows, capture is real: Rust records the mic and system audio, cancels the call's echo out of the mic track, and transcribes them locally with whisper.cpp, then removes filler words with delete-only rules (the raw words are kept). On macOS the others' voices are also told apart after Stop, and an English live transcript switches to Parakeet (both through sherpa-onnx). The browser preview and Linux keep a **prototype** capture that records nothing. There is no automatic summarization, cloud sync or accounts. Summary suggestions are opt-in: when the user asks, Claude (their own Anthropic key) or a model in Ollama on their computer drafts suggestions from a recorded transcript, and only what the user adds is written. Do not fabricate behavior (e.g. inventing summaries, transcripts or audio). The only runtime network use is user-initiated: Connections (sending action items to Linear or GitHub) and summary suggestions with Claude (sending a transcript's text to Anthropic, and the user's notes when enhancing them). The speech models are downloaded at build time only.

Upstream Scratch code is retained, not rewritten. The QuietNote shell lives in `src/quietnote/` and `src-tauri/src/meetings.rs` and reuses Scratch's editor, services and Rust commands. `docs/SCRATCH-AUDIT.md` (pre-change audit) and `docs/MODIFIED-FILES.md` (diff manifest vs. upstream) are the reference for what was changed. Keep `docs/MODIFIED-FILES.md` in sync when touching upstream files.

Playwright needs Chromium (`npx playwright install chromium`). Tests run serially (1 worker) against the browser preview in fresh contexts, so they never touch the real desktop archive. Tests J–X drive the desktop recording UI through `mockDesktop(page, fixture)`, a hand-written stand-in for `window.__TAURI_INTERNALS__` that models only the recording commands and events (fixture: meetings, microphone permission, model status, a live recording, a start failure; it also models pause/resume, the microphone list, `window_compact` (`state.compact`) and the live draft, which a test sets in `state.draft` before emitting `quietnote://live-transcript`, as Rust does; `plugin:event|unlisten` removes the listener, so React's development double-mount doesn't leave duplicate handlers). It also stubs `save_file_direct` (last content in `state.saved`), `capture_allow_microphone` (`state.micAnswer`), browser sign-in (`state.signInServices`, `state.pendingSignIn` to resolve or reject, links opened in `state.opened`), the summary commands (`state.summaryKey`, `state.suggestions`), `mcp_agents`/`mcp_agent_set` (`state.agents`), the clipboard plugin (`state.clipboard`) and `call_accessibility` (`state.accessibility`). `docs/QA-RECORDING.md` is the manual real-device checklist, `docs/PERFORMANCE.md` the measured numbers, and `docs/WINDOWS.md` the untested Windows risks.

CI (`.github/workflows/ci.yml`) runs `npm run build`, `cargo check` and `cargo clippy -- -D warnings` on Ubuntu (which doesn't compile the recorder), plus clippy on all targets and `cargo test` on macOS with the models cached; lint, typecheck and Playwright must be run locally. The release workflow is manual (`workflow_dispatch`) and creates a draft only; the upstream Scratch update feed is disconnected (update checks are gated on `VITE_QUIETNOTE_UPDATES`).

## Architecture

### Two apps in one bundle
`src/main.tsx` picks the root component from the URL:
- default → `QuietNoteApp` (the meetings shell)
- `?workspace=…` or `?mode=preview` → upstream Scratch `App` (generic Markdown workspace / standalone file preview), lazy-loaded
- `?panel=call&app=…` → `CallPanel` (the call detection panel window, see `calls.rs`), lazy-loaded

The Scratch workspace is reachable from Settings → Local archive → Open Markdown workspace, and links back to QuietNote from its About screen.

### QuietNote shell (`src/quietnote/`)
- `QuietNoteApp.tsx`: single `Shell` component that owns all state (meetings, projects, view, selection, save status, drafts, banners, keyboard shortcuts, window-close handling). `compact` is the Granola-style window beside a call: the call panel's Start recording (`recordCall`, once the meeting exists) calls `window_compact(true)`, and the shell drops the sidebar, the window bar's navigation (an Open full window button instead), the recording bar and the editor's `[data-format-bar]`, leaving the meeting and its recorder. Open full window, or any view other than the meeting (a shortcut, the tray), calls `window_compact(false)`. Views: home / all / actions / project / meeting / search / settings / people (a remembered `recent` from earlier builds opens Home). The sidebar's *Action items* shows the open count across meetings. The sidebar has no logo or wordmark (they stay in Onboarding, the call panel and About). Double-clicking its divider (or Enter on it) switches between icons with labels and icons only (`rail`, remembered as `quietnote.rail`), caught in capture on the `aside` so Scratch's `SidebarResizeHandle` (whose own double-click resets the width) stays unmodified; as icons only the divider doesn't drag. Windows 720px wide or less are always icons only (`narrow`, from `matchMedia`) and have no divider. With no projects and no meetings it renders `Onboarding` instead of the shell. The last view, meeting and tab are remembered in localStorage (`quietnote.place.v1`; a tab from earlier builds, Summary/Decisions/Action items, opens Enhanced). `openMeeting` without a tab uses `model.openingTab`.
- `Onboarding.tsx`: first launch, one idea per screen with Back and step dots (each step keyed, so a click that moves on can't land on the next step's button). Steps are fixed when it opens: hello (Get started; Explore example meetings), how it records (when recording is available), the microphone (macOS, while not yet granted: the reason first, then `capture_allow_microphone`, which asks macOS without recording; denied shows Open System Settings; Not now leaves the recorder's first-run explainer for later), the calendar (macOS: Use my calendar sets `calendar` and asks; Skip), one skippable question (the kind of meeting: picks `noteTemplate`, which `model.templateFor` uses when the title doesn't suggest one, and names the project), and the first project (prefilled, `createProject`). Illustrations are shapes and the app's own labels, never words anyone said. Nothing records here.
- `Hush.tsx`: Hush, the mascot whose face shows what QuietNote is doing (designed in the Paper file "QuietNote — Mascot"). `Hush({ mood, size, look })` draws the Paper shapes as one SVG; moods are real states only: resting, ready, listening, paused, transcribing, suggesting, done, attention, winding. Its styles and keyframes are the "Hush" section at the end of `quietnote.css`: each mood rests on its Paper pose (a mood's last face in `FACES`) and animation only adds to it (sway from the feet, breathing, uneven blinks; the transcribing split, the suggesting bubble, the done hop and check and the attention lean play once, on Apple-style spring curves in `linear()`), and `prefers-reduced-motion` holds the pose. Listening turns the eyes to the side that's talking (`useLook` over `Capture`'s `useLevels`, held 1.2 s), never a scripted glance. Where he is: the Home capture card (instead of the status dot; while transcribing the card is about the transcription, with a progress bar, and `progress` closes the pieces up as the percentage climbs), the call panel (ready; winding during the stop countdown), a meeting's transcribing (with its progress) and problem notices (attention), the drafting notice in `SuggestPanel`, the "Recording saved" / "Transcript ready" banner (transcribing / done; not on Home, where the card has one), resting in empty states (enhanced notes and transcript unless recording or drafting, Action items, People, no meetings, no search results), and one line on the onboarding hello. One per screen is enforced with `HushYield`: the Shell sets it while the banner has Hush, `MeetingDetail` while a notice has one (and leaves out the empty state's while `SuggestPanel` reports `onWorking`), and a yielding `Hush` shows its fallback (the icon or illustration he replaced); on macOS the menu bar icon is Hush too (see `tray.rs`). Settings → Appearance → *Show Hush* (`showHush`, default on, enforced) turns him off: `showHush()` sets it for every `Hush` in a window (the Shell from its preferences, the call panel from `quietnote_preferences` and `quietnote://preferences-changed`, which that command now sends to the call window after a write), and a hidden `Hush` renders its `fallback` (the Home card's status dot, the call panel's `Logo`) or nothing; Onboarding leaves out its Hush line (`useHushShown`).
- `Library.tsx`: `MeetingList` (rows grouped by day; today's show the time; a row without a status shows its open action-item count) and `Home`. Home is laid out top to bottom:
  - A capture card built from `CaptureState`, with Hush in the mood it's in: ready, mic denied (Open System Settings), model missing, recording (Open meeting only, on Notes; Stop stays in `RecordingBar`, so there's never a second one), transcribing (titled "Transcribing on this Mac", with a progress bar, the % and the queue; Start recording stays), or prototype. Start recording calls `newMeeting()`.
  - A search field that switches to Search.
  - Open action items from every meeting (the first six; *All action items* opens the Action items page). A tick goes through `persist` + `toggleAction`, and a ticked item stays struck through until you leave Home.

  `ActionItems` (view `'actions'`) is Granola's planned Action Items page: every meeting's items under their meeting (title opens its enhanced notes, date, project), newest first, with an Open / Done switch. A tick goes through `toggleItem` and the item stays where it is until you leave or switch.
  - The ten latest meetings.

  Empty sections are hidden.
- `Dialogs.tsx` (`Modal`, new project, new meeting; with `canRecord` its primary button is "Start recording", which creates the meeting and starts recording it, and "Create meeting" is secondary), `Capture.tsx` and `Settings.tsx` (Privacy / Appearance / Local archive / About). `Capture` is not a dialog: `MeetingDetail` renders it last, as a bar pinned to the bottom of the meeting (region "Recorder", `.recorder-dock`, sticky in `.qn-main`; the article becomes a full-height column via `.docked` so the bar sits at the window's bottom even with short notes) while its meeting is armed to start (the Shell's `capture`, dropped on leaving the meeting or when its recording stops) or recording, so Notes and the transcript stay usable above it. It renders `Recorder` when `CaptureState.available` (a view over Rust state). Its line has a level button (combined bars from `quietnote://levels`, peak per track ten times a second from `Health::take_levels`) that folds the details drawer (open unless closed before, `quietnote.drawer.v1`), Recording/Paused, the recorded time (`model.recorded`: `recordedMs` plus the time since `resumedAt`, which is null while paused), the microphone picker (`MicPicker`: System default or a named device from `capture_devices`; `capture_set_device` switches a running recording and keeps the choice) and Pause (Resume while paused, in the same place) + Stop, labelled briefly (the one primary is Stop, or Resume while paused). The drawer holds the consent line ("Let everyone know you're recording.") with Copy message (`consentMessage`, to paste into the call's chat; QuietNote never types into the call app), the `LiveTranscript` (unless the Transcript tab is open, which shows it instead), and per-track meters with device names (call audio says "waiting for others" until someone else speaks). Device problems, notes and silent-track hints with Open System Settings sit between drawer and line. While the mic permission is `undetermined` it expands into the first-run explainer with Cancel / Start recording instead of starting automatically, so the explanation always comes before the macOS prompt; a `mic-denied` start failure shows Open System Settings and Try again. Otherwise it renders `Prototype` (browser preview and Linux: `idle` → `recording` → `ready` from the meeting's metadata, records nothing, no simulated processing). There's no "ended" step: after Stop the bar goes and the meeting's transcribing notice takes over. `LiveTranscript` shows `capture_live_transcript` then `quietnote://live-transcript` for its meeting as bubbles (You right, Others left, clean or verbatim), follows the newest unless scrolled back (Jump to latest), and shows dots for a side whose level was loud in the last 1.5 s: never invented words.
- `model.ts`: `Meeting = { metadata, markdown, transcript }` plus pure helpers for reading and writing `##` sections of `meeting.md` (`section`, `replaceSection`, `toggleAction`, `appendAction`), parsing (`actionItems` with `Owner — task`, `transcriptTurns` from `### mm:ss Speaker`, `enhancedNotes`: the Summary section plus an earlier build's Decisions section as a `### Decisions` heading, so it's never hidden), where a meeting opens (`openingTab`: Enhanced once it has enhanced notes, action items or a transcript, else Notes), and search context (`searchMeeting` returns the matching tab, Enhanced / Notes / Transcript, and a snippet). The **Notes** section is always last and consumes the rest of the file, so headings inside notes survive.
- `storage.ts`: persistence facade that branches on `isTauri()`:
  - **Desktop**: `invoke()` calls into `meetings.rs` for archive load/create/metadata/preferences. Markdown is saved with Scratch's `saveFileDirect`. On load it points Scratch's notes folder at the archive root and starts its file watcher, so Tantivy search (`indexedSearch`) works over meeting files.
  - **Browser preview**: everything goes to `localStorage` (`quietnote.preview.archive.v1`, `quietnote.preview.projects.v1`, `quietnote.privacy`). It never migrates into the desktop app.
  - Desktop saves are recorded in `ownWrites` so the watcher's `file-change` events for QuietNote's own writes don't trigger the "Files changed outside QuietNote" prompt. Rust's `transcript.md` writes are recorded the same way when `quietnote://meeting-changed` arrives.
  - Recording: `captureStatus`/`captureStart` (rejects with `CaptureFailure { code: 'mic-denied' | 'disk' | 'failed', message }`)/`captureStop`/`capturePause`/`captureResume` (rejects like start)/`captureDevices`/`setCaptureDevice`/`liveTranscript`/`transcribe`/`transcriptData`/`renderTranscripts`/`revealAudio`/`openPrivacySettings`. The Shell keeps `live: CaptureState` from `quietnote://capture-state` and upserts meetings from `quietnote://meeting-changed` (metadata, a finished transcript, or a problem shown as a banner). While recording, `RecordingBar` in the window header shows Recording or Paused, the title, the recorded time (`model.clock`, the same format as the tray), Resume while paused, and Stop in every view except the recording meeting itself, where the recorder bar has the only Stop. The tray's Pause/Resume/Stop run in Rust; a failure arrives as `quietnote://capture-problem` and shows as a banner. However a recording stops (recorder, bar, tray, low disk), a "Recording saved" banner (then "Transcript ready") with Open meeting says where it went, unless that meeting is open. A banner lists meetings with `interrupted` ("Recovered recording").
- `MeetingDetail.tsx`: two tabs, Notes and Transcript, as in Granola. `MeetingTab` is `'Enhanced' | 'Notes' | 'Transcript'`: the Notes tab has an *Enhanced notes* / *My notes* switch (group "Notes view") and comes back to whichever was shown last. Enhanced notes are the meeting's action items (`.note-actions`: checklist, *Add an action item*, Send to…), leading the note once there are any and after it until then, then `enhancedNotes` through `model.summaryBlocks`, with `SuggestPanel` on top for a recorded meeting; without enhanced notes it says *No enhanced notes yet.* and how to get them. There are no decisions: new meetings have no Decisions section and nothing adds to one. My notes lazy-loads Scratch's real `components/editor/Editor` inside `NotesBoundary`, so an editor failure shows "Notes couldn't open." with Reload instead of blanking the window; `Crashed` in `QuietNoteApp.tsx` does the same for the whole shell. The summary and action items are parsed from Markdown, not stored separately. An idle meeting's Start recording is its primary action, starts at once and switches to Notes (there's no confirm step; the first-run explainer still waits); New meeting's Start recording also opens on Notes. A recorded `ready` meeting has a secondary Resume recording that does the same, recording more into it. The header status says Paused while its recording is paused. While a meeting is idle or recording, My notes opens with `LastTime`: the previous meeting's open action items (ticking one ticks it in that meeting, through `persist`; it stays struck through until you leave), from `model.previousMeeting` (the latest earlier meeting of the same series, by title unless it's a made-up "… call"/"Untitled meeting", else the latest earlier one in the project; only when it left an action item open; examples only lead to examples). `model.summaryBlocks` reads `###` headings, lists and paragraphs, and a list item's trailing `[mm:ss]` is a transcript link; such lines (added from the transcript) are muted. Notices for a recovered recording (`interrupted`, with Dismiss), transcribing (progress) and error (with audio: "Transcription couldn't finish. Your recording is still saved", Show audio, Retry transcription, and the stored `error` under Details; without: the interrupted copy). Start recording is disabled while another meeting records. `find` prefills Find in transcript when opened from a transcript search hit. Turns show the speaker only when it changes, and not at all when only one side spoke (the same in `LiveTranscript`). A recorded transcript has a Clean / Verbatim toggle (default from the `cleanTranscript` preference, with a caption); both views come from `transcript_data` and switching never writes. While recording (live transcript on) and while processing, the Transcript tab shows the live draft, labelled, after any earlier transcript (a resumed meeting); the full transcript replaces it when `meeting-changed` brings it.
- Calendar in the shell (`QuietNoteApp.tsx`, while `preferences.calendar`): `events` (today's, re-read every minute and on focus; the first read waits for the preference write in `queue`), `newMeeting(event?)` (without one, `calendar_now` fills the dialog when found), `newMeetingFor(eventId)` (the tray), `recordCall` names the meeting after `calendar_now`, `projectOf` (`model.projectFor`: the series' last project, else where those attendees' meetings are, else the context project). `NewMeetingDialog` takes `event`/`projectFor`: title and project come from it until typed over, with "From your calendar · 14:00–14:30 · 2 others" and *Don't use*. Home's `UpNext` lists today's remaining events (max 3) with *Prepare notes* (creates the meeting from the event, never recording) or *Open notes*. `CallPanel` shows the current event's title. `model.makeMeeting(title, project, event?)` dates the meeting at the event and fills `participants`, `attendees`, `calendarEvent`, `calendarSeries`; `previousMeeting` prefers the same `calendarSeries`.
- `People.tsx` (view `'people'`, sidebar *People*, `Place.person` = a person's key or `@domain`): `model.people` (from `attendees` without `me`, or typed `participants`; key = email or name; `company` = the email domain unless a personal provider or the user's own domain; newest first) grouped by company with a search, and a page per person or company with their open action items (`model.owns`: the owner is their full or first name or email; ticking goes through `toggleItem`) and their meetings (`MeetingList`). Empty state points to Settings.
- Naming in `MeetingDetail.tsx`: the `<h1>` is a `Title` button (editable unless recording or transcribing) whose input saves through the Shell's `renameMeeting` (`saveMetadata`, then `persist(model.retitle(...))`); on a recorded transcript a voice's label is a button opening the "Name “Speaker 2”" form (datalist of invited names) → the Shell's `renameSpeaker` (`transcript_rename_speaker`, then `upsert` with the returned transcript); with exactly one other person invited and one other voice, "Is “Others” Maria Lopez?" names it from the invite without a model. `SuggestPanel` adds *Name the meeting and speakers…* (when `model.madeUp(title)` or unnamed voices remain): a confirm saying the transcript and invited names are sent → `meeting_names` → *Title and names* (Use / Dismiss, each name with its citation).
- `Connectors.tsx` (Zoom, Meet and Teams entries show Built in where call detection runs; `ConnectionsDialog`, the searchable directory opened from the sidebar; `SendDialog`, which sends a meeting's unsent open action items as issues) and `catalog.ts` (directory entries). Brand logos are static SVGs in `src/quietnote/brands/` (credited in NOTICE). Apple Calendar, Reminders and Things icons are read from the installed apps via `connector_app_icons`, with a letter tile as fallback. `issueFor` in `model.ts` builds the issue from an item. Only entries with a `service` (Linear, GitHub) connect; all others are Planned and have no action. A sent item keeps its link at the end of its Markdown line (`linkAction`, parsed into `ActionItem.link`). Example meetings can't be sent.
- `Suggestions.tsx`: `SuggestPanel` also offers *Enhance notes…*: a confirm notice (what's sent: the notes and the transcript's text, for Claude) with a template picker (`noteTemplates`, preselected by `model.templateFor` from the title) and *Edit templates* (`openTemplates`) → `notes_enhance` → an *Enhanced notes* preview (lines from the transcript with their citation, lines from the user's notes with their quote) → *Use these notes* (*Replace enhanced notes* when there are some) writes `model.notesMarkdown` into Summary. It never touches Notes. The rest: `SuggestPanel`, shown in the enhanced notes of a recorded meeting when the Shell's `summarizer` is ready (`summaryProvider` `anthropic` with a saved key, or `ollama` with an `ollamaModel`). *Suggest from transcript…* → a confirm notice that says what leaves the device → `summary_suggest` → a Suggestions panel: summary (Use as / Replace summary) and action items (Add / Dismiss, through `appendAction` / `replaceSection` and `persist`), each with its citation (timestamp + quote; clicking opens the Transcript tab and highlights `.transcript-turn[data-time]`), and how many were dropped. ### Rust side
- `src-tauri/src/meetings.rs`: QuietNote commands (`load_meeting_archive` returns `{ root, projects, meetings }` where projects are top-level archive folders; `create_project`; `create_meeting_bundle`; `save_meeting_metadata`; `quietnote_preferences`). Metadata and preferences are written atomically (temp file + rename). Path components are validated with `safe_component`.
- `src-tauri/src/oauth.rs`: signing in through the browser with no QuietNote server (RFC 8252). One `PROVIDERS` row per service holds everything that differs: Linear uses the system browser with PKCE and a loopback redirect (`PORTS` 47821–47823 tried in order, each registered as `http://127.0.0.1:<port>/callback`; access tokens last a day and refresh with the client ID alone); GitHub uses the device flow (its browser flow needs a client secret). Client IDs are public and set at build time (`QUIETNOTE_LINEAR_CLIENT_ID`, `QUIETNOTE_GITHUB_CLIENT_ID`); without one, that service takes a pasted key. `quietnote://sign-in` tells the window what to open (and GitHub's code); `connector_sign_in_cancel` stops waiting. A redirect with another `state` doesn't end the wait. The window comes to the front when it's done.
- `src-tauri/src/connectors.rs`: Linear (GraphQL) and GitHub (REST) via `reqwest`. `connector_sign_in` (through `oauth`) or `connector_connect` (a pasted key) verifies the account before storing the tokens or key in the macOS Keychain; a signed-in token is kept as JSON (`oauth::Tokens`) and refreshed before it expires, a key as itself (`keyring`, macOS-only dependency; other platforms return an error). Keys never return to the webview. Account labels go in `<app data>/connections.json`. `connector_app_icons` reads installed app icons through `NSWorkspace` (`objc2-app-kit`). All HTTP happens in Rust, so the CSP has no `connect-src`.
- `src-tauri/src/capture.rs`: the recording/transcription lifecycle and its commands (`capture_status`, `capture_start`, `capture_stop`, `capture_pause`, `capture_resume`, `capture_devices`, `capture_set_device`, `capture_live_transcript`, `transcribe_meeting`, `transcript_data`, `render_transcripts`, `open_privacy_settings`). Managed state `Capture` holds the one live `Session` and a FIFO transcription queue with a single worker thread; `claim()` allows one recording at a time. A `Session` counts recorded time as `recorded` (before the current run) plus the wall clock since `wall`, so pauses don't count and window and tray agree; its `Health` outlives each run of the recorder. `pause` stops the recorder (finalizing the WAVs and releasing the mic) while the meeting stays `recording`; `resume` restarts it appending to the same files (both under the session lock, so a stop can't land halfway). Starting a `ready` meeting records more of it (only if it has `transcript.json` or an empty `transcript.md`, so a written transcript is never replaced): kept audio is appended to, otherwise new files are made, and `metadata.resume` (`resume_point`: `atMs` after the earlier recording and its last words, `sample` where the new audio starts in the files) makes `process` transcribe only the new part and add it with `transcript::append`; `save_transcript` clears it and recovery accounts for it. `LiveText` (off/loading/on/failed) is reported per recording; `begin` spawns `live::spawn` when the `liveTranscript` preference (default on) and the model allow, and `Capture.draft` keeps the latest `Draft` until the worker finishes that meeting. `State` also carries the microphone permission and the model status (ready/missing/damaged). Rust owns a meeting's status while it records or transcribes (`owns`; `save_meeting_metadata` refuses those meetings): `idle` → `recording` (audio folder set) → `processing` → `ready`, or `error` with the audio kept and the reason in `metadata.error`. Start is refused below 1 GB free; the ticker warns below 1 GB and stops cleanly below 150 MB. `save_transcript` writes the transcript, then `ready`, and only then deletes audio (`deleteAudio`); `record_failure` never deletes. The worker writes `audio/.transcribing` with an attempt count; `recover` (at setup) repairs WAV headers (`repair_wav`), flags crashed recordings `interrupted` and queues them, re-queues an interrupted transcription once, and after two crashes leaves it as `error` for the user. `shutdown` finalizes a live recording on Quit and `RunEvent::Exit`. `pause_on_sleep` (macOS, `NSWorkspaceWillSleepNotification`) pauses a running recording before the Mac sleeps and sets a note; it waits for Resume. `pause_media` sends MediaRemote's pause command (`mac::pause_media`, private framework loaded with `CFBundle`; pause never starts playback) when recording starts or resumes. `process` transcribes, then on macOS (`SEPARATES`) labels the others' pieces by voice (`separate` → `speakers`) before merging, with transcription shown as 90% of the progress; a failure there only leaves "Others". Reads `cleanTranscript` (default on), `deleteAudio`, `liveTranscript` (default on), `echoCancellation` (default on), `separateSpeakers` (default on) and `pauseMedia` (default on) from `.privacy.json` via `meetings::preference`, and `inputDevice` via `meetings::preference_str` (`meetings::set_preference` writes it).
- `src-tauri/src/recorder.rs` (macOS/Windows only): cpal capture on a dedicated thread (streams aren't `Send` everywhere). `start(dir, health, append, cancel_echo)`: with `append` (resume) `even_tracks` first pads the shorter WAV with silence, then the writers continue the files with `WavWriter::append`. Mic from the device chosen by name (`Health::with_mic` / `choose_mic`, which reopens a running stream; listed by `input_devices`, without QuietNote's own `SYSTEM_DEVICE`), or the default input when none is chosen or it isn't connected (a note says so, and it switches back when it reappears); system audio from a private aggregate device over a global Core Audio process tap on macOS (`mac::SystemTap`, works even when the output device has its own mic) or WASAPI loopback on the default output on Windows. Writer threads downmix, resample to 16 kHz (rubato `Fft`), write i16 WAV with hound and `flush()` every second (crash-safe); they pad silence by wall clock so both tracks stay aligned. With `cancel_echo` (the `echoCancellation` preference, default on) the system writer shares what it writes (`Played`, by track position) and the mic writer runs each 4 ms block through `Canceller`: WebRTC's AEC3 `BlockProcessor` from `sonora-aec3` (pure Rust) after Sonora's high-pass filter, with the call audio of the same position as reference, waiting up to 200 ms for it. Only the linear filter's output is written (AEC3's suppressor muted the user under continuous call audio), and a block that would come out louder than it went in is kept as it was; `written` counts what the canceller still holds, so padding stays on the clock. While the live transcript follows (`Health::follow`), every sample written (padding included) is also kept in `Health`'s feed for `take_feed`, so the live timeline is the file's. `watch` keeps each track on a live device: it reopens a lost stream, one that stopped delivering audio for 3 s (mic, and the macOS tap, which delivers even in silence; not Windows loopback), or one whose system default changed (mic; Windows output), and records a problem ("Microphone disconnected…") or a note ("Microphone changed to …") in `Health`, with device names. macOS mic permission is read and requested through `AVCaptureDevice` (`microphone_permission`, `MIC_DENIED`). `SystemTap::device` waits up to 3 s for Core Audio to publish the aggregate device (each attempt has a unique uid).
- `src-tauri/src/transcribe.rs` (macOS/Windows only): whisper-rs (Metal on macOS) with the bundled `ggml-large-v3-turbo-q5_0.bin` and Silero VAD (`ggml-silero-v6.2.0.bin`), resolved from `BaseDirectory::Resource` (`models/…`, set in `tauri.macos.conf.json` / `tauri.windows.conf.json`) or `resources/models` in debug builds. `status` checks presence and size (pinned in `MODELS`, same pins as `scripts/fetch-models.mjs`); `verified` checks the full SHA-256 once per session before loading. Windows loads the main model from memory (non-ASCII profile paths). Silero VAD finds speech; `chunks` groups it into ≤25 s chunks cut only at real pauses, each transcribed on its own (greedy, `no_context`, language detected once from the longest chunk). Token timestamps split output into timed sentences (also at 1 s word gaps); `align` anchors each start to the speech it overlaps and `mark_pauses` flags sentences after ≥0.5 s silence. A chunk with a decoder loop (`find_loop`: a 2–8-word phrase three times in a row) is retried with beam search, and any remaining repeats are cut (`collapse_loops`, `drop_repeats`). **No initial prompt**: in testing Whisper repeated the meeting name as if spoken. `run` can start at a sample and offset the times (a resumed recording). The per-chunk step (`transcribe_span`, `speech`, `language`) is shared with `Engine` (macOS), which keeps the model, a state and the VAD loaded for the live transcript and uses 4 threads.
- `src-tauri/src/live.rs` (macOS only): the live transcript. `spawn` turns on the recorder's feed and runs a thread that loads the `Detector` (Silero VAD) and Whisper's `Engine` (the recording has already started) and every 3 s takes the feed, finds speech per track, and transcribes the chunks `ready` says are finished (followed by 600 ms of silence, ≤8 s chunks, forced after 25 s, or everything when paused), then merges all pieces so far with `transcript::merge` and sends the turns (`capture::set_draft` → `quietnote://live-transcript`). The language is settled on the first chunk of 4 s or more; if it's English, `Words` switches once to `Parakeet` (freeing Whisper), steps every second, and also transcribes the speech still going on (`Track.speaking`, redone each step, shown but never committed). Without the Parakeet model it stays with Whisper. It ends with the session and frees the model (`Following` drops the feed). Nothing is written to disk; the full pass after Stop makes the kept transcript. Measured in `docs/PERFORMANCE.md`.
- `src-tauri/src/speakers.rs` (macOS only): tells the others apart after Stop. `voices` runs sherpa-onnx's offline diarization (pyannote segmentation 3.0, 3D-Speaker ERes2Net VoxCeleb embeddings, fast clustering at `THRESHOLD` 1.0, chosen with the accuracy test, a half-window `SHIFT`, about 2 minutes per hour on an M3 Pro) over `system.wav` (only the resumed part when recording more); `label` gives each system piece the voice it overlaps most, or the nearest within 1 s, as "Speaker N" in order of first speech, numbered after an earlier part's (`numbered`). Fewer than two voices leaves every piece "Others". Models pinned in `MODELS`, like Whisper's.
- `src-tauri/src/parakeet.rs` (macOS only): NVIDIA Parakeet TDT 110M (int8, English) through sherpa-onnx's offline transducer recognizer, 2 threads. `pieces` turns tokens with timestamps and durations into timed sentences (`sentences`: ends at . ? ! or a 1 s gap, punctuation tokens joined without a space) and aligns them like Whisper's. Files pinned in `FILES` under `models/parakeet-tdt-110m-en-int8/`.
- `src-tauri/src/ax.rs` (macOS only): reads a running browser's window titles, `AXDocument` addresses and tab titles (radio buttons anywhere inside an `AXTabGroup`, title or description, breadth-first within `BUDGET`/`DEPTH`, 0.5 s messaging timeout) for `calls`. `trusted`/`ask` wrap `AXIsProcessTrusted(WithOptions)`. `dump` (test only) prints an app's element tree.
- `src-tauri/src/mcp.rs` (all platforms): `quietnote mcp` (`cli::run` hands it stdin/stdout before buffering): a Model Context Protocol server, JSON-RPC 2.0 one message per line with `serde_json`. `initialize` (echoes a version in `VERSIONS`, else the newest), `ping`, `tools/list`, `tools/call`; notifications get no reply, unknown methods `-32601`. Tools `list_meetings`, `list_projects`, `search_meetings`, `get_meeting`, `get_transcript` call the CLI's functions (`Options`, `list`, `show`, … are `pub(crate)`); a problem is the tool's result with `isError`. The archive is found per call (`cli::archive`). Read-only. Settings → Local archive → *Use with AI apps* copies `mcp_config` for any other app (this binary with `mcp`, not Scratch's nohup `install_cli` wrapper, which would swallow stdio).
- `src-tauri/src/agents.rs` (all platforms): one-click MCP setup. `APPS` lists each AI app's settings file (Claude Desktop, Claude Code `~/.claude.json`, Codex `~/.codex/config.toml`, Cursor, VS Code `servers` with `type: stdio`, Windsurf, Gemini CLI, LM Studio); `mcp_agents` returns those whose folder exists (a home-level file: the file) with `state` on (runs this binary) / other (a `quietnote` server running something else) / off / unreadable, and `mcp_agent_set(id, on)` adds or removes `quietnote`, keeping the rest of the file (key order via serde_json `preserve_order`, TOML via `toml_edit`) and any extra keys of an existing entry. ChatGPT is absent on purpose: it only reaches remote MCP servers. Settings' `AiApps` shows a switch per app, *Use this copy* for `other`, and re-reads on focus.
- `src-tauri/src/calendar.rs` (EventKit on macOS; commands answer empty or "unavailable" elsewhere): only while the `calendar` preference is on (default off; Settings → Privacy → Use your calendar asks for access via `calendar_access(true)`; the Calendar usage strings are in `Info.plist` and `com.apple.security.personal-information.calendars` in `Entitlements.plist`). `mac::events` reads every calendar on the Mac for a range, skipping all-day, untitled and declined events. `Event { id: eventIdentifier@startMs (occurrences of a recurring event share an id), series: calendarItemExternalIdentifier, title, startMs, endMs, attendees, link }`; `attendee` turns EventKit's name and `mailto:` URL into `meetings::Attendee { name, email, me }`; `meeting_link` finds a Zoom/Meet/Teams/Webex/Whereby link; `current` is the event happening now or starting within 10 min (a call link first). - `src-tauri/src/cli.rs` (all platforms): the read-only `quietnote` command. `main.rs` runs `scratch_lib::command_line` first, and only its commands (`meetings`, `show`, `transcript`, `search`, `projects`, `help`) replace the app; anything else (a file path) starts the app as before. - `src-tauri/src/transcript.rs` + `cleanup.rs` (pure, all platforms): `merge` labels mic pieces *You* and system pieces *Others* (or their `Piece.speaker` from `speakers`), drops mic echo of the call (`split_echo`, per sentence: the same words in order as call audio playing when the sentence began, with its start within 2.5 s or its end within 1 s; a whole piece under 3 words must match exactly within 0.7 s; when unsure the sentence stays; dropped sentences are kept in `Transcript.echo` for diagnostics only), and joins same-speaker pieces into turns (a new turn after a 2 s gap, or once a turn has run 15 s, so long talking reads as timed paragraphs), recording a `breaks` offset where a heard pause and a capital both mark a sentence Whisper left unpunctuated. `markdown` renders `### mm:ss Speaker` turns, clean or verbatim; `Turn::clean` is the clean text. `cleanup::clean` returns delete-only byte ranges (fillers like um/uh/erm/hmm, stutters and repeated 2–3 word phrases, the pause comma before a filler) and `render` applies them, adds full stops at `breaks`, and tidies punctuation/capitalization. It deliberately keeps context-dependent words ("like", "you know", "I mean"), self-corrections ("2… actually 3"; the comma before a number or name stays), numbers and number words, capitalized repeats (names), quoted speech, and a capitalized filler with no pause mid-sentence (a name). "ah"/"eh" count only as comma-wrapped pauses mid-sentence. A capitalized filler mid-line ("…to confirm Hmm, that works") marks a new utterance, so `clean_with_breaks` adds a break there rather than running two sentences together.

### On-disk archive
`<app data>/app.quietnote.desktop/meetings/<Project>/<YYYY-MM-DD-slug>/` holds `metadata.json` (duration in **seconds**, status `idle|recording|processing|ready|error`, relative paths), `meeting.md` (title/date/project/duration, then Summary, Action items as `- [ ]`, Notes; meetings from earlier builds may also have a Decisions section, shown in the enhanced notes), and `transcript.md`. Recorded meetings also have `audio/mic.wav` (echo-cancelled unless turned off) + `audio/system.wav` (16 kHz mono) and `transcript.json` (raw turns with cleanup `removed` ranges, speakers "You", "Others" or "Speaker N"; `transcript.md` is rendered from it). Transcript text lives **only** in `transcript.md`/`transcript.json`, never in `meeting.md`. `audioPath` is `<Project>/<id>/audio` or null (validated in `bundle`). Optional metadata `interrupted` (recovered after a crash, until dismissed), `error` (why the last transcription failed), `resume` (`{ atMs, sample }` while recording more of a finished meeting is being recorded or transcribed), `calendarEvent`/`calendarSeries` (the event occurrence and series it was made from) and `attendees` (`[{ name, email, me? }]` from the invite) are omitted when unset. `audio/.transcribing` exists only while Whisper runs. The root also holds `.privacy.json`, `.scratch/settings.json` for Scratch compatibility, and `.initialized` in archives from earlier builds that auto-seeded demos. The separate identifier keeps it isolated from a real Scratch install.

### Window lifecycle
Closing the main window (red button, ⌘W) hides it and QuietNote keeps running in the menu bar / tray. `on_window_event` prevents the close in Rust, and the Shell's `onCloseRequested` always calls `preventDefault()` (otherwise Tauri's JS wrapper destroys the window) and saves pending notes. The tray, a Dock click (`RunEvent::Reopen`) or a relaunch restores the same window. Quit QuietNote first finalizes a live recording in Rust, then emits `quietnote://quit-requested`, and the Shell saves pending notes and calls `quietnote_quit`. Rust exits anyway after 3 s. ⌘Q exits immediately, because Tauri can't intercept it; recovery drafts cover unsaved notes, `RunEvent::Exit` finalizes the recording best-effort, and `recover` repairs the audio on the next launch. Standalone preview windows close normally.

### Saving and recovery
Notes are saved through the editor's debounced save. Every keystroke also writes a recovery draft to webview storage, which is retained on save failure and offered for retry/reload. On desktop, `capture::recover` handles interrupted `recording`/`processing` meetings on disk (recovered audio is transcribed; no audio → `error`). In the browser preview they load as `error` in memory ("Needs attention", with Mark as ended). Outside edits raise a "Files changed outside QuietNote" banner with an explicit Refresh; there is no conflict merging.

### Retained upstream Scratch patterns
- `NotesContext` uses a dual context pattern (data/actions separated) for performance.
- Scratch settings: app config at `{APP_DATA}/config.json`, per-folder at `{NOTES_FOLDER}/.scratch/settings.json`.

## Product principles

QuietNote is private and bot-free (see the landing page copy in `../Meetings Application/src/content`). Anything that touches Connections or capture must hold to these:
- Never join a call, add an attendee or use a meeting bot. Call awareness (Zoom/Meet/Teams) may only be detected locally on the Mac.
- No calendar auto-join and no capture before the user presses start. A calendar may pre-fill a meeting, never start one. The calendar is read through EventKit on the Mac, only while turned on, and never changed. The tray may open New meeting, but only its Start recording button starts recording.
- Audio and transcription stay on the device. Summary suggestions send a transcript's text (only the text; enhancing notes adds the user's notes and the template, naming adds the invited people's names), only when the user asks for that meeting, and only to the provider they chose with their own key; local Ollama sends nothing. Generated items are suggestions until the user adds them, every action item must cite the transcript, and every enhanced-notes line must quote the transcript or the user's notes. A recording may stop by itself (the call ended, a long silence), but only after a visible countdown the user can cancel; it never starts by itself. Recording captures only the mic and what the computer plays (a local tap/loopback), never by joining the call. Keep filler cleanup delete-only and keep the raw words available (Verbatim).
- Data leaves the device only on an explicit user action (e.g. Send), and only the minimum (see `issueFor`). Drafts (email, Slack) are reviewed by the user before sending.
- Keys and tokens live in the macOS Keychain, never in webview storage, and never go back to the webview. There is no QuietNote server: sign-in connectors use native-app OAuth (RFC 8252: system browser, PKCE, loopback redirect, or a device flow where the browser flow needs a secret; `oauth.rs`) with tokens kept on the Mac, unlike cloud assistants (e.g. Grok) whose servers hold the tokens.
- Don't claim "fully offline", compliance certifications or end-to-end encryption.

## Coding Conventions

- Clean, minimal code with low technical debt. Don't add commented-out code or TODOs.
- Match the terse style of `src/quietnote/` when editing there (compact one-line helpers, no heavy abstraction).
- Use `React.memo` for expensive list items and `useCallback`/`useMemo` on hot paths.
- Debounce user-triggered operations (auto-save 300ms, search 150ms, file watcher 500ms, git status 1000ms).
- Keep operations async and non-blocking, and surface errors visibly. Corrupt or unreadable archives must show an error rather than silently resetting data.
- Planned privacy settings only record intent. Keep them in the "Planned" group unless they are actually enforced (`cleanTranscript`, `deleteAudio`, `liveTranscript`, `echoCancellation`, `separateSpeakers`, `pauseMedia`, `confirmMeetings` and `calendar` are enforced when recording is available; the last four are macOS only). Where recording is real the Planned group is hidden, so every setting shown there does something; the browser preview keeps it. Real user meetings must show only data that exists: use empty states ("No summary yet.", "Transcript unavailable."), never generated placeholders.
- Only one cobalt-filled (`.primary`) action per context; everything else uses `.secondary` or `.text-button`. Base element resets in `quietnote.css` use `:where()` so class rules aren't out-specified.
- Preserve Scratch attribution (LICENSE, NOTICE, About/Privacy screens).
